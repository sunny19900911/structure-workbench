# 工程参数来源与成果联动

将同一项目的资料、采用参数与下游成果连成可追溯流程，避免多份数据各自改动或旧项目状态串入新项目。

## 数据职责

先读既有架构，确认项目与单体的稳定ID、唯一参数源、保存位置及导出接口。不要只因当前页面DOM可读取就把它作为全部上下文；修补已有单向接口优先于重建系统。

区分：
- 原始资料：文件版本/哈希、来源位置、原单位与原表格。
- 提取候选：值、单位、项目/单体、来源、置信/异常信息；提取不是工程采用。
- 采用参数：采用值、来源依据、适用条件、确认状态和版本。
- 派生成果：消费哪个参数版本、哪些内容自动生成、哪些人工编辑。

自动提取明确且无冲突的普通信息可直接形成草稿；缺失、冲突和工程判断集中给人处理。不让每个机械步骤都增加确认框。

## 联动规则

参数源单向驱动下游，PPT等显示字段通常只读；下游需要局部覆盖时建立显式覆盖记录，不悄悄回写源值。区分设计条件联动与模型计算：修改设防参数不能宣称已经重新求解。

维护参数到章节、表格、图表的依赖关系，只更新受影响内容。上游变化使相关确认失效并显示待复核；不能只隐藏确认按钮而留下无法解除的状态门槛。

自动正文和人工改稿分别管理。重新导入、更换来源、AI改写须预览差异，保留人工稿；AI可自由改写用户要求的文字，但联动标记和已确认数据的变化必须可辨认。撤销应恢复文本与引用状态。

移除来源时清除仅由该来源支撑的候选/采用值；人工覆盖及另有来源支撑的同值保留并说明理由。恢复来源应重新核验，不直接恢复旧“已确认”状态。

项目切换须隔离资料、对话、异步请求结果、缓存和保存状态。请求发出时绑定项目ID，迟到响应不得写入当前另一个项目。

## 验收

用两个隔离项目和合成数据验证：
1. 参数更新进入所有受影响成果，非相关章节不变。
2. 人工正文不被重新导入覆盖，更新冲突可解释和撤销。
3. 来源移除、共享来源、恢复后再确认；不残留孤立结论。
4. 项目切换期间收到迟到响应，不串项目；刷新后恢复一致。
5. 页面、导出与保存读同一快照；模板中的示例值不能渗入真实项目。
6. 单位与汇总口径正确。强度型指标按分母加权，例如各层kg/m²汇总用总重量/总面积，不平均各层比值；缺面积不按零处理。
7. 规范结论具备项目条件、地区、版本和原文依据；来源公告与PDF全文身份分别核对，缺项保持待核。

交付字段/依赖映射、变更处理规则及实际测试结果。历史实现可能已迭代，复用前读取当前项目约定，见 [references/evidence.md](references/evidence.md)。
