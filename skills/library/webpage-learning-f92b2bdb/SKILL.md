# 用网页学习

目标是帮助用户理解和应用，而不是把聊天内容原样塞进网页。用户偏好中文、具体场景和逐步展开的解释，尤其关注AI编程、时间精力管理及神经科学。

## 选择流程

- 普通图文解释：根据范围选用可用的 `visualize`、`frontend-app-builder` 或 `sites:sites`，生成真正可打开的HTML或本地网页，遵循所选技能的规则。
- 明确要求深度、系统学习、研究型展示或学习看板：先读取并使用 `superlearn` 的SKILL.md。按其流程调研、保存证据、组织学习路径、制作可交互看板。需要公开部署时仍遵守用户的发布授权要求。
- `superlearn` 缺少运行环境、脚本或依赖时，检查真实资源后作等效适配；实在无法运行，则明确说明限制，使用其他网页工具交付同等目标的网页，不假称运行过Superlearn。
- 用户已指定其他平台、已有网页或只改一处内容时，保持其选择，不另建整套产品。

## 内容要求

先澄清“要理解什么、为什么与用户有关”，从一个具体问题进入，再逐步讲概念、关系、机制和应用。围绕用户目标选择篇幅，不堆术语和无意义模块。

“数据详实”指证据充分：可变、专业或拿不准的事实先核查，优先原始论文和官方资料。数据、图表、引文标明来源及时间；解释性示意与实测数据分清。不要为了显得丰富而编造数字、论文、视频或效果承诺。

图文并茂应至少有帮助理解的图示，如关系图、机制流程、时间线、对照图或可操作小例子，按主题选择。图不能只作装饰。图中结论与正文证据一致；能用HTML/SVG清楚表达的示意可直接实现，需要位图插画时使用可用的图像生成技能。

页面应支持手机阅读，层次清晰，可通过目录、渐进展开或交互例子降低一次阅读的信息量。只在能帮助用户时添加交互，不机械堆卡片。学习页面以理解为目的，保留用户明确指定的测验或练习偏好。

## 交付

把产物保存在当前项目已有的输出目录；没有约定时用 `output/learning-pages/<topic>/`。检查链接、图文、关键交互和手机布局。交付实际可打开的文件链接或运行地址，不能只给HTML代码或说已经生成。

默认本地交付，不自动上公网。结束时按 `project-skill-memory` 记录本次确实有效的技能和证据；仅规划或读取过的技能保持待验证。
