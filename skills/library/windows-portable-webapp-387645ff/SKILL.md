# Windows 网页应用离线交付

交付让另一位用户能独立解压、启动、保留数据和恢复项目的应用包。先判定核心操作依赖浏览器、后端、系统Office还是云服务；不要把“免安装”写成“零依赖”。

## 包装与启动

- 复用现有应用结构与锁定版本的构建。随包携带允许分发且匹配架构的必要运行时，记录版本、来源和许可证；先检查已有运行时，不为打包全局升级环境。
- 启动器以自身目录定位程序，正确处理中文、空格和非ASCII路径，不依赖当前工作目录、开发机绝对路径或管理员权限。
- 后台助手隐藏窗口；保留可诊断的启动日志和可见错误说明。对端口占用先辨认是否本应用及兼容版本，不终止未知进程，也不把占用端口的别的网站当作成功。
- 在真正健康就绪后打开浏览器；失败要给日志位置和退出状态。重复启动的行为明确，避免同时写同一数据库。
- 用户数据、程序与临时文件分离。目录按当前项目约定或用户选择；更新程序不覆盖项目，测试数据不得进入交付包。
- 配置以占位或用户本机输入交付，真实密钥不随包。基础离线操作与可选联网AI分别列出；“未使用AI也可运行”不能写成“AI完全离线”。

## 文件能力与迁移

检测真实文件格式而非只看后缀。将原生支持、转换支持、部分可读、加密、损坏和不支持分开反馈。扫描OCR结果需与原页对照，工程数据特别检查负号、小数点、上下标与表格列。

若精确Word分页或旧DOC转换依赖本机Office，明确该条件并提供不依赖它的功能边界。生成了下载文件仍须重新打开或渲染核对内容，不以文件非空代替验收。

项目导出包应包含结构化数据、实际引用附件和清单；仅有备份JSON未必能跨电脑恢复。缺失附件显式列出，不悄悄去掉引用。导入应防路径逃逸、重复ID和覆盖现有项目。

## 验收矩阵

在新的中文带空格目录解包验证，尽可能使用非开发环境：
- 不调用系统Node/Python，基本离线流程完成；若未在干净机器验证，写明仍依赖当前电脑证据。
- 首次启动、重复启动、冲突端口、关闭和再次打开；只清理测试自建进程。
- 建立隔离项目→导入代表文件→修改→保存→重启→重新打开。
- 导出实际成果并检查关键文字、表格、图像与页码；分“内容正确”和“版式正确”。
- 导出项目→在新数据目录导入→比对内容和附件哈希。
- 用演练数据验证升级前后保留、缺依赖错误与故障日志。

交付ZIP、清单、使用说明、已测环境和待测项；包大小及本机通过不保证所有Windows版本兼容。历史依据见 [references/evidence.md](references/evidence.md)。
