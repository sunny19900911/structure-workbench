# 非论文任务的个人执行规则

本技能由用户级AGENTS.md接入，可跨工作区使用。仅处理非论文场景；是否暂停或恢复论文由当前用户要求及项目约定决定，本技能不设置全局暂停状态。

## 按实际交付物加载

只读相关文件；混合任务可组合，不必全部加载。

| 交付物或操作 | 场景文件 | 与现有技能的关系 |
|---|---|---|
| 网页、表单、应用、集成、打包、复刻 | [product-software.md](references/product-software.md) | 新建/重设计沿用frontend-app-builder；部署、设备和便携包用各自专业技能 |
| 工程资料、参数联动、计算书、CAD成果 | [engineering.md](references/engineering.md) | 沿用engineering-parameter-sync及对应工程工具流程 |
| 公众号、客户报告、非论文Word/PPT | [reports.md](references/reports.md) | 文档/演示文稿技能负责格式与渲染；本文件负责受众和内容取舍 |
| 软件演示录屏、字幕、配音与成片验收 | [demo-validation.md](references/demo-validation.md) | 文案偏好沿用reports.md；本文件处理证据核对与制作交接，不操作录制服务 |

提及其他技能不是加载全部技能的要求；实际使用时读取可用的原技能，缺失时说明限制。

## 开始与结束

- 从项目文件和当前要求确定读者、任务范围、认可版本、实际入口、输出位置。只询问确实无法推断且会显著改变结果的事项。
- 小任务直接做；复杂任务用一句话说明本轮交付目标。明确只讨论时不修改成果，已授权执行时自主完成可推进部分。
- 简洁意味着删重复和过程自证，保留关键事实、例子、数据、完整目录和行动步骤。用行业常用词，不生造缩略表达。
- 用户纠正后检查当前成果所有同类位置。只有明确可复用的偏好才更新场景文件；不保存聊天原文或凭据，不将一个项目的参数变成全局默认。
- 交付用已观察结果说明完成程度。未实际操作、渲染或连接设备的部分如实列出，不用脚本通过代替真实效果。检查限于本次改动、相关依赖和已知故障，不为小改扩大工作量。

## 改进是否有效

发生新纠正时可在该任务已有工作记录中简短记下：问题类别、是新要求还是规则未执行、修正及验证结果。不要为了统计建立常驻监控或抓取聊天。积累三次同类任务后，检查重复纠正是否减少，再调整规则。当前规则已接入，实际减少干预的效果仍待真实任务验证。
