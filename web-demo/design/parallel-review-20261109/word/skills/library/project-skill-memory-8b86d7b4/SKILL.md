# 项目 Skill 沉淀

每个项目的索引是 `skills/技能沉淀.md`，副本在 `skills/library/`。先查索引再决定复用哪些Skill，不要一次加载全部副本。

## 使用后沉淀

- 用户已授权默认记录有效技能，无需每次再次询问。用户本轮要求只读或不要沉淀时，尊重该要求。
- 只有读取说明或了解过能力时，标“待验证”。确实使用并产出有效结果后，补齐用途、成果、验证依据和可直接复用的自然语言指令，才标“已验证”。失败的方案标“有待改进”，不要当作推荐做法。
- 使用 `~/.codex/hooks/personal_workflow.py record` 更新索引和副本。示例（参数中的路径替换为本轮真实路径）：

```powershell
python "$env:USERPROFILE/.codex/hooks/personal_workflow.py" record --project "当前项目路径" --skill "实际读取过的SKILL.md绝对路径" --use-when "适合解决什么问题" --example "用户下次可以直接说的话" --outcome "本次实际产出了什么" --validation "真实检查结果或可核对的产物路径"
```

- 不记录用户原文、完整对话、密码、密钥或私有素材。只记录可复用的方法摘要和产物位置。
- 副本保留SKILL.md及安全的脚本、引用、资源和元信息；有省略或用户改动时索引会提示。不要默认为复制Skill就安装了原插件、MCP连接或外部依赖。
- Hook在结束时会把检测到的说明读取留为“待验证”；不要为了让它变成“已验证”而补造结果。

## 再次调用

用户要求调出沉淀技能时，先读当前项目索引，按目标列出少量最相关的技能、适用场景与调用句子。执行时优先读取当前仍可用的原技能；源文件缺失时读取项目副本，并检查其中引用的资源与依赖。不要将整个库自动加入上下文。
