# 扫描范围符号重排复验

source_id: QA-LINGANG-RANGE-REFLOW-20261109。局部OCR实验结果，非工程采用值。

## 方法与结果

临港扫描PDF物理第17页的范围上下限分三行印刷。此前360dpi单元格裁切虽恢复数字，范围符号仍被漏读或读成m。新增 `ocr-line-layout.py`：按像素投影寻找2～4行，将各行原有像素矩形按从上到下顺序横向摆放，记录原图/输出坐标与哈希；不生成字符、不依据OCR结果修复数字。检测到暗像素丢失或重复则原样返回。单行和超过4行保持原样。

本地MinerU basic CPU识别，逐项核对原页及裁切图：

|固定比较集|原始裁切|原像素横排后|
|---|---:|---:|
|先前3个困难层厚范围|1/3|3/3|
|新增6个层厚范围、3个负高程范围|3/9|9/9|
|另保留3个平均值对照|3/3|3/3|

12个范围合计由4/12完整正确提高到12/12，需同时匹配两端数字、负号与范围符号。只归一Markdown标题/转义、空白和全角波浪号；不把m、r、2等识别错误替换成范围符号。它们来自同一页，不代表12页、全报告或其他工程的准确率。新增9格未参与本次方法调整，但仍属于同页留出样本。

示例：`1.50 m 3.71` → `1.50~3.71`；`-25.88 2 -28.62` → `-25.88~-28.62`。后三个负高程范围全部保留负号。没有将层厚平均值并入范围。

## 真实执行与检查

首次引擎运行94.531秒，包括默认设备探测与模型获取，最终CPU；随后显式沿用原CPU与测试缓存配置，新增9格横排/原样对照分别18.219/18.312秒。不是纯推理耗时比较。原PDF SHA-256与此前读取一致。15张输入的矩形像素逐块精确一致，暗像素数量相等；增加保护后的6张初始输入与实际OCR输入哈希一致。

3项像素排布测试和3项原生PDF读取回归通过。原件只读，实验只写QA；没有改生产上传、项目数据、依赖或运行包。
