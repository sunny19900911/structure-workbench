# 扫描表裁切复提验证

source_id: USER-PDF-REEXTRACT-20261109。本轮只读临港报告物理第17页，在隔离 QA `pdf-crop-round` 复提；不改原件，不自动采用识别值。

## 结论

高清重绘、按字段裁切能改善数字粘连，但没有解决范围符号和层号的可靠识别。暂作为复核辅助，不能替代整页阅读或作为无人复核的参数导入方式。

使用同一个本地 MinerU basic CPU 引擎，将原来的整页180 dpi输入改成360 dpi渲染后六个裁切区域，分别读取三行层厚范围和平均值。坐标由原页人工核对指定，并非已实现自动表格分割。执行成功，约20.6秒，无 Windows 应用程序控制拦截；原PDF读取前后SHA-256一致。

这三个困难样本的六个上下限数字全部恢复；只有一行同时正确保留范围符号。其余两行保留原始OCR与原图供复核，不自动补写范围符号。平均值另行输出，但未纳入这六项统计；不能把拆开的平均值与范围重新拼接成一个数，也不能用范围推算平均值。

## 证据与复跑

- `pdf-crop-round/manifest.json`：输入、页码及归一化坐标。
- `crop-provenance.json`：源文件哈希、360 dpi像素坐标、原件未改变记录。
- `images/`：六张原始裁切图，补白边，无人工改字。
- `results/`：六份引擎原始JSON/Markdown；`ocr.status.json`记录退出状态。
- `checks.json`：只检查独立数字串，不将该项通过等同范围语义正确。

复跑 `crop-ocr-regions.py <manifest.json> <images目录>`，然后使用既有 `run-bounded.py` 调用 `benchmark-mineru.py <images目录> <results目录> basic`。渲染使用bundled Python、Poppler，OCR使用已有QA环境和本地模型缓存。

下一步应验证自动定位单元格及范围符号的专门识别，并扩充其他页面的固定样本；在这之前不把本实验接入正式上传入口。此前原生文字PDF的表格恢复成果仍有效，本轮收益限于上述扫描表样本。
