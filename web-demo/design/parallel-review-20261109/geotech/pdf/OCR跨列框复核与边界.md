# OCR跨列框复核与边界

source_id: QA-OCR-COLUMN-GUARD-20261110-R93。陈述类型：本机实测事实。

新增`ocr-column-guard.py`，用显式列边界检查OCR四边形：只在整个框完全位于单列时给出列索引；跨列或越出表范围时不给索引，保留原始文字、检测框及所有重叠列。不按数字格式拆字符串、不按框中心强行归列、不裁断框。所有结果automaticAdoption=false。本组件只核查几何，不证明字符正确或表头已经验证。

4项测试通过：合并数字串保留且拒绝归单列、贴边不算跨列、越界不夹回、非法/空几何拒绝。

对R92五页真实输出，列边界由R26原始自动网格及已知裁切、32像素白边、2倍比例计算，没有使用expected答案。核验5张来源图和5张OCR输入图的SHA256，排除表头范围后分别检查默认合并与关闭合并两组。

- 默认合并：86个数据文本框中6个跨列，包含全部4个已知粘连串26.017.9、14.711.3、21.014.3、25.010.7，也包括两处正确的22.0。
- 关闭合并：90个数据框中8个跨列，这8个文本在R92人工基准中均正确，但检测框包含列外留白。其余82个框只能说几何上位于单列，不能据此保证数字正确。

因此不能把跨列标记当作真实错字，也不能放宽边界使本批全部通过。严格检查是复核候选生成器，尚不能独立决定自动列归属。后续需要按原列几何重新裁切识别，并保存冲突、原值和复提值；不能用相邻数值大小或期望答案纠正。

真实证据：`web-demo/qa/parallel-review-20261109/geotech/goal-round93/column-guard-audit.json`，保留所有框、原文、来源/输入图哈希、变换后列线。未改正式读取器或工程参数，未新增文档导出。表头/孔号核验和跨列候选复提仍待完成。
