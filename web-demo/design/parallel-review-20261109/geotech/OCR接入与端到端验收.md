# 困难页 OCR 与原件端到端验收

source_id: USER-OCR-E2E-20261110（用户要求：执行端到端验收并接入困难页OCR；缺项最后统一提示，尽量简短）。

## 已接入

- 本机源码版上传PDF后，先读原生正文/表格，再检查扫描页、未映射字形、未解决的跨格数字及疑似未恢复网格。检测区分页框/分栏与表格，避免普通页框触发整页OCR。
- 困难页使用已有本地PPOCRv6模型，以两种分辨率读取；保存原PDF哈希、物理页码、文字位置、两次读数及一致性标记。相同读数不等于正确，不调用云端模型、不下载模型、不自动采用OCR数值。
- 识别结果进入当前来源的`ocrReview`，保存与重开保留；展开现有来源原文可查看“OCR待核”文本。纯扫描件有识别结果时可导入待核来源，不再因为没有原生文字而一律拒绝；没有识别结果仍明确失败。
- 上传一批文件结束后，仅保留一条简短提示，例如“已处理；3页待核。”；无待核项为“已处理。”。重试使用相同提示。没有新增常驻缺项清单、逐项确认卡片或正文红字。
- 原生提取失败仍不静默退回旧读取。OCR故障保留原生内容及待核页；取消请求停止识别，不把部分结果当作完整结果。

## 运行边界与配置

- 使用现有本机OCR环境和本地模型。配置读取`WORKBENCH_OCR_PYTHON`、`WORKBENCH_OCR_MODELS`，或忽略目录`web-demo/outputs/pdf-ocr-runtime.json`；其中只有本机绝对路径，不含密钥。配置不随Git分发。
- 每份先处理最多8个困难页，扫描页优先；OCR阶段限180秒，原生读取限165秒，上传等待370秒。超出页数、超时或识别失败仍保留待核标记，提示不把“跑过OCR”说成“已核验”。
- 这是本地图像OCR与双分辨率一致性对照，不是视觉大模型的语义审查。化学式、电荷、层号、公式和复杂表格的正确行列映射仍须复核，OCR候选不自动填入正文或设计参数。
- 本轮未扩展Word页眉/页脚/内容控件解析，也未重新打包离线版；此前`WorkbenchPortable`分支边界不变。

## 复验入口

在工作树根目录，指定本机文档Python及隔离QA_URL后运行：

```powershell
node web-demo/design/parallel-review-20261109/geotech/end-to-end-acceptance.mjs <冻结清单.json> <本轮输出目录>
node web-demo/design/parallel-review-20261109/geotech/end-to-end-export.mjs <本轮输出目录> <冻结清单.json>
node web-demo/design/parallel-review-20261109/geotech/ocr-upload-browser.mjs <原PDF路径> <隔离输出目录>
```
