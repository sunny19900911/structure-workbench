# 文章、客户报告与非论文PPT

## 执行规则

- 先判断读者和用途。报告先给结论与依据，文章从具体问题展开，PPT突出成果与有依据的收益；不强套同一结构。
- 正文保留帮助理解和行动的内容；内部编号、生成过程、审核流水放到必要的工作记录，不堆进交付正文。
- 用具体解释替代连续否定与空泛自证。影响读者判断的真实限制仍简短说明，不靠删除条件夸大结论。
- 保留事实、关键参数、例子和操作步骤，删除重复概念、碎句、排比与空泛总结。用户要详实报告时不能压成提纲。
- 不自动披露无关个人背景，不强行关联AI；不编造收益、科学依据或确定性。
- 按既有模板和认可样式排版，颜色只用于有限强调；旧任务的绿色偏好不扩展成所有项目统一配色。

- 软件演示视频以实际操作和可见结果为主；有本人样片时沿用其讲法，仅去重复口语。旧样片涉及过时功能、格式或指标名称时，依据当前实际能力纠正，并同步脚本、字幕和配音，不为照搬原声虚构当前能力。不要将录制机制、测试自证或无关免责话语塞进字幕和旁白。讲参数联动时同时交代源字段和结果位置，以鼠标、标注和停留帮助观众看见变化。

## 交付检查

- 读者能否回答：解决什么问题、依据是什么、接下来能做什么？
- 检查全篇同类措辞和重复内容，不只改用户点名的句子。
- 对照需求与模板检查必要内容，再按现有文档/PPT技能完成渲染检查；不能以文本检查代替排版验证。

## 正反例

- 空泛：该结果不能证明对所有人有效，不能替代任何判断。更合适：明确样本和使用条件，解释本次结果支持的具体行动；必要风险保留。
- 错误：把详实客户报告精简成五条口号。正确：压缩重复背景，保留结果、实例、依据和步骤。
- 错误：汇报页展示任务编号、代理状态、校验日志。正确：展示已完成成果、效果与待决事项；内部记录独立保存。
