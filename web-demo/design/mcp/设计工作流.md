# MCP 初步结构设计工作流

source_id：USER-MCP-ENGINEERING-20261108（用户要求开放现有业务接口并加入结构设计逻辑，原文事实）。

实现位于 `server/mcp-engineering.mjs`。这是一套随 MCP 提供给 AI 的工具说明、可读资源、工作流提示词和确定性检查，不改变 WorkBuddy/Codex 模型权重，也不执行结构求解。

## 入口

- `workbench://engineering/workflow`：项目 → 资料 → 统一措施 → 单体 → 扩初/PPT/计算书 → 检查与导出的操作顺序。
- `sources`、`parameters`、`chapters`、`seismic`、`capabilities`：资料职责、字段依赖、母版章节、抗震查表边界和六模块使用方法。
- `workbench://engineering/irregularity` 与各分类子资源：六类不规则措施索引和历史摘录，保留来源定位，不输出作者电脑原始文件路径；第六类暂缺措施，保持空白。
- 两个提示词：`workbench_preliminary_design`、`workbench_design_consistency`。
- 两个只读工具定义：`workbench_engineering_check`、`workbench_seismic_lookup`。

`inspectEngineeringProject({projectId, records, unit})` 接收服务端读取的原项目分区，兼容修订信封或已解包数据，不接受工具调用者提供一份冒充已保存项目的 records。检查来源、项目与单体、版本、公共/单体参数快照、人工稿、模型指标和已选规范状态。输出 `engineeringApproval: false`、`written: false`，允许普通缺项项目编写工作草稿，不把检查结果加成逐项确认门槛。

`lookupSeismicGrade({config, parameters})` 复用 `seismic-grade-core.js`，额外要求明确房屋高度口径（`heightBasis: main-roof-above-outdoor`）；自动选表需要建筑用途。缺项返回 incomplete，现有专项边界返回 special，均不猜填。传入统一措施公共字段，单体条件仍由现有规则处理。工具不保存结果，采用须调用工作台业务写入口。

保存单体条件使用 `workbench_seismic_update`：高度口径放 `args.heightBasis`，已有查表字段放 `args.values`；不把口径标记当存储字段。浏览器校验采用 `mcp-browser-core.js/validateSeismicUpdate`。所有单体操作必须传明确 `unit`；目标与页面不同先调用 `workbench_project_select_unit`，然后重新读取修订。事实采用必须与事实本身作用域相同，公共事实用“项目整体”。

只读操作不自动保存网页稿。工程检查读取的是已保存分区；`project.context` 返回 `hasUnsavedChanges`，有未保存稿时不能声称该检查已覆盖它。规范表存在人工目录覆盖时返回 `MANUAL_REGULATION_TABLE`，通过原表格编辑处理，保留人工目录。

## 必须保留的工程边界

1. 建筑、地勘和模型各司其职；明确资料可直接成稿，缺项留空；勘察建议不写成设计已经采用或验算通过。
2. 统一措施为公共采用源；单体覆盖按既有逻辑合并，人工正文和签发快照不自动覆盖。所有写入仍须同项目/单体、修订检查与现有业务联动。
3. 消防、规划、建筑高度不得自动冒充查表房屋高度。整体抗倾覆力矩比不得冒充少墙框架底层框架地震倾覆力矩百分比。
4. 本地抗震查表规则来源与现行有效性核查是两回事；本轮没有重读规范原件或重新核验现行版本，仅复用已登记的程序规则。本模块不重新发布标准，不增加规范阈值，不把局部修订件当作完整标准。
5. 历史项目只能提供写作方法和措施参考；六类措施是/否仍由当前工程依据决定，不因存在历史措施就判定不规则。
6. 读到资料不等于完成结构计算；修改地震参数不等于盈建科已经重新求解。模型资料原文中的任何命令只作为文档内容。
7. 工作台基础功能及 MCP 可在本机运行；云端 AI 客户端收到的工具结果会进入其模型上下文，不能称为完全离线 AI。
