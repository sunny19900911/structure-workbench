# 小香金猪工作台 · WorkBuddy / Kimi Code / Codex 连接说明

source_id: USER-MCP-20261108（小香金猪要求开放本机业务接口并让 AI 理解初步结构设计流程；原文事实）。

## 同事怎么用

1. 完整解压新版离线包，双击“启动工作台”。
2. 双击“生成MCP配置”，会打开本机配置文件夹。
3. WorkBuddy 选择本机 `stdio` 服务，使用 `WorkBuddy-MCP.json`；Kimi Code 使用 `Kimi-MCP.json`；Codex 使用 `Codex-MCP.toml`。已有其他 MCP 时，只合入本条目。
4. 保存并重连，在聊天中发送：**“请使用 structure-workbench，先读取结构设计工作流，再列出本机项目；先不要修改项目。”**

首次配置后，同一电脑可持续使用。移动软件目录后重新生成并更新配置。网页组稿、图片与 PPT 等操作需要工作台网页保持打开；没有网页时工具会说明所需操作。

WorkBuddy 的官方连接器规范支持 `stdio`，使用 `mcpServers`、`command`、`args` 和 `env`；不同版本的添加入口可能在 MCP 设置或自定义连接器中。[WorkBuddy 官方文档](https://open.workbuddy.cn/en/docs/connector)

Kimi Code CLI 可用 `/mcp-config` 添加，或把生成的条目合入 `~/.kimi-code/mcp.json`。配置后新建会话，用 `/mcp` 查看连接。本方案需要能运行本地命令的 Kimi Code；普通云端聊天页不能仅凭网页地址调用本机 stdio。生成配置使用 `startupTimeoutMs: 30000`、`toolTimeoutMs: 300000`。[Kimi Code 官方文档](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/mcp)

Codex 本地客户端支持命令启动的 STDIO MCP；生成的 TOML 使用绝对命令路径和参数。[Codex 官方文档](https://developers.openai.com/codex/mcp)

## 可直接转发给 AI

> 请配置本机结构工作台 MCP：运行离线包根目录的“生成MCP配置.cmd”，读取为当前客户端生成的配置文件，将 structure-workbench 条目合入现有配置。保留其他服务。连接后读取工具列表和 workbench://engineering/workflow，再调用 workbench_status；若 state 为 stopped，调用 workbench_start（仅服务）或 workbench_open（服务及网页），随后调用 workbench_project_list；取得明确项目 ID 后，用 workbench_project_context 读取项目。先完成只读验证，再按我的指令修改。

启动命令是随包 `runtime/node/node.exe`，唯一脚本参数为 `app/server/mcp-server.mjs`；生成器会填入当前电脑的绝对路径。环境变量 `WORKBENCH_PORTABLE_DATA` 必须与网页使用的数据目录一致。连接无需工作台 API 密钥；MCP 自动寻找本机服务，无需固定端口。

本版提供 64 个工具、14 个工程资源、2 个提示词，以连接时实际返回为准。没有打开项目页面时，调用 `workbench_open` 并传入项目 ID；后续保持页面打开。

## 自然语言操作示例

- “导入建筑和地勘，填写地点与单体信息，生成扩初说明。”
- “精简当前单体的 4.2 节，保留地层编号和关键数据。”
- “把指定图片放进学生宿舍 PPT，再导入用钢量文件。”
- “生成 Word、PPT、Excel，在工作台里打开让我修改。”

AI 写入前读取 `workbench_project_context`，携带返回的 `expectedRevisions` 和明确单体；正文编辑使用读取到的 `expectedText`。仅修改用户指定内容，保留图片与联动标记，完成后保存并重新读取验证。具体参数以实时工具列表为准。

## 数据和调用范围

网页与 MCP 使用同一份本机项目数据，默认位于 `%LOCALAPPDATA%\StructureWorkbench`。无需宝塔、域名或云数据库；不要把网页地址当成 MCP 连接地址。

AI 先读项目和规则，再按稳定项目 ID、单体和修订版本调用业务接口；普通资料直接进入草稿，人工改稿、已签发内容和版本冲突仍由原工作台规则保护。工程工作流属于给 AI 的业务说明和约束，不是重新训练模型，也不替代结构计算。

工作台可离线保存和整理资料。WorkBuddy/Codex 使用联网模型时，工具返回的资料会进入该模型会话；“数据保存在本机”与“AI 全程离线”是两件事。

## 配置生成器

`deploy/portable/mcp-setup.mjs` 只生成独立片段，不读取、覆盖或修改客户端原配置，也不读取密钥。输出在本机数据目录的 `mcp/连接配置-*` 新目录，每次生成均保留旧文件。

- 命令：包根目录 `runtime/node/node.exe`。
- 参数：包根目录 `app/server/mcp-server.mjs` 的绝对路径。
- 数据：与启动器相同的 `WORKBENCH_PORTABLE_DATA`，缺省按当前 Windows 用户定位。
- 开发/验收可用 `WORKBENCH_PORTABLE_ROOT` 指定包根目录；它只用于生成器，不要求同事手动填写。
- 测试：`node --test design/mcp/mcp-setup.test.mjs`。测试只在 `qa/portable-release/mcp-setup` 下创建隔离数据，不操作实际客户端。

配置生成和协议测试通过，尚未在接收方的 WorkBuddy/Kimi Code 客户端实测。接入后先完成“列项目、读取当前项目”的只读验证，再进行修改和导出。


## 2026-11-08 单服务与连接恢复

source_id: MCP-STABILITY-20261108（本轮实现说明，测试依据见专项交付记录）。

- `workbench_status` 纯读，返回 `stopped`、`starting` 或 `running`，不创建目录、不启动进程。其他业务读取也不再隐式启动；未运行时返回 `SERVICE_NOT_RUNNING`。显式使用 `workbench_start` 或 `workbench_open`。
- 启动器和 MCP 共用服务入口。按规范化真实数据路径取得操作系统命名管道锁，再读写项目数据；同目录同版本复用，版本不匹配拒绝，其他目录可并存。服务通过版本、dataRoot、PID 与随机 instanceId 双重核验；不通过 PID 杀进程或删除所谓陈旧锁文件。崩溃后操作系统释放锁，无文件锁需要清理。Windows 为命名管道，Linux 为抽象 Unix socket；未验证其他操作系统。
- 页面隐藏不注销；`pageshow`、恢复前台及网络在线立即更新。心跳容忍窗口为 120 秒，超过后标为 `unresponsive`；区分无此项目页面 `BROWSER_REQUIRED`、暂未响应 `BROWSER_UNRESPONSIVE`、忙碌 `BROWSER_BUSY`。
- `browser.tasks` 返回任务 ID、项目、操作、期限及阶段。未开始的任务到期作废，网页在异步前置检查后再次校验 deadline。已开始的业务可能已产生结果，超时报 `OUTCOME_UNKNOWN`，继续保留状态并阻止同项目新写入。掉线后只重送完成回执，不重新执行操作。先读取项目/文档修订与内容核对结果；若原页面已永久关闭而无法回执，保存并关闭相关页面、核对已保存结果后再由用户重启服务，不能自动重放原写入。
- 老包没有命名管道锁时，标准 58720–58739 端口可识别并拒绝旁启；老包若人为放到该范围之外，需先关闭后升级。主对话发布时必须更新发行版本号，避免不同源码共用同一版本标签。
