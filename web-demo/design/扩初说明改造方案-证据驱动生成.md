## 3. 首次生成：先组织依据，再组织文字

### 3.1 四类输入各司其职

| 输入 | 提供什么 | 使用边界 |
|---|---|---|
| ①统一技术措施 | 已确认设计参数、结构体系、材料、荷载及特征开关 | 是设计采用值的唯一编辑入口；发现冲突要复核 |
| 当前建筑、地勘 | 单体与场地事实、使用功能、柱网跨度、地质条件及地勘建议 | 提取成候选事实；地勘推荐不自动等于设计采用 |
| 当前模型 `.out` 文件组 | 模型输入、计算工况和实际结果 | 与统一措施并列核对，不覆盖设计采用值 |
| 601规范与602写作方法 | 适用要求、写作规则、相似案例与反例 | 历史项目的地点、尺寸、结果不得自动进入项目事实 |

不要把“人工确认 > 规范 > 历史”等排列当作统一裁决器：人工确认决定本项目采用值，但不能使规范冲突自动消失；规范约束、模型实际值和资料事实各自保留。

### 3.2 导入后先形成事实表

每项事实保存：项目、单体/结构单元、部位或楼层、字段、数值与单位、原文定位、文件版本、`source_id`、陈述类型、确认状态及冲突项。

- 区分建筑高度、结构高度，区分绝对标高和相对标高，区分地勘建议与设计决定。
- 识别“无、拟、建议、尚未、相邻项目”等语境；关键词命中只用于检索线索。
- 不把多单体报告混成一套值；模型文件也要绑定单体、模型批次和计算方案。
- 正文生成前只集中确认影响最大的缺项与冲突，其余章节可以先出草稿。
- 缺少资料用空项或待核状态表达；示例项目数据只存在于显式演示模式。

### 3.3 历史项目沉淀为可审核规则

复用已有602写作方法库，规则增加：`rule_id / version / applicability / required_evidence / narrative_outline / prohibited_claims / source_ids / review_status`。

例如“结构选型”写作规则要求说明：**建筑需求 → 已选体系 → 与需求的关系 → 模型复核情况 → 尚未解决的限制**。它提供分析顺序，不提供预填的工程结论。

离线从多个案例提炼规则，保留原文出处和反例，人工确认后再投入生成。运行时主要给模型“规则＋当前证据”；完整历史成品不默认进入初稿上下文。必要的案例仅作为带标签的辅助材料。

已有体系确定时，解释真实依据和约束；体系未定时，将备选方案放进“待决定”区域。不得为使文章完整，虚构曾做过的方案比选、经济性结论或“经计算满足”。

### 3.4 分章生成的六步流程

1. **冻结输入版本**：参数、资料、模型、规范和写作规则共同形成一次生成快照。
2. **建立章节提纲**：沿用现有十章及条件章节，选择本项目应出现的内容。
3. **组织可检查的依据**：每章记录“已知条件、已确认决定、引用依据、未决项”；这些是审核摘要，不要求展示模型内部思维过程。
4. **调用 DeepSeek 成文**：按章传入相关证据和规则，返回正文块、引用、参数引用、待核问题；失败只重试该章。
5. **程序校核**：检查引用存在性、单位、数值、参数绑定、单体归属、模型批次和禁用历史值；再检查语义冲突。
6. **形成可编辑初稿**：缺项影响局部内容，不以空泛套话填满；有依据的章节仍可继续编写。

生成质量不以“与历史文字是否相似”单独判断。通用技术表述可能相同，重点检查本项目依据是否充分，以及历史专属事实是否被误用。

## 4. 参数联动和文本编辑

### 4.1 正文使用三种内容块

| 内容块 | 用户操作 | 数据变化后的行为 |
|---|---|---|
| 参数/事实引用 | 点击查看来源；通过原编辑入口修订 | 草稿中显示新值，并记录变化 |
| 可编辑叙述 | 直接修改、批注、锁定、DeepSeek 改写 | 保留人工稿，标出受影响段落 |
| 计算结果/规范引用 | 查看工况、条文、版本与判据 | 重新校核；不直接宣布原结论仍有效 |

参数在正文里显示为正常文字，编辑时表现为可点击字段；底层保存字段引用，而非复制一个数字。人工输入与参数重复的数字或等级时，提示绑定或列为待核，不允许无提示脱链。

### 4.2 变更传播规则

- 参数值变化：关联数字更新；涉及选型理由、措施、适用规范的段落标记“需复核”。
- 结构特征变化：相关章节提示显示/隐藏，人工内容仍保留。
- 新模型导入：旧模型的结果及结论标记过期，新旧批次不能混用。
- 规范版本变化：列出受影响章节、计算判据和待确认参数，先看差异再采用。
- 已签发文档：固定其全部输入和正文版本；修改进入新修订版，不改变旧签发件。

“更新受影响内容”只提出增量建议。人工稿与新建议冲突时，比较旧生成稿、人工稿、新建议稿，逐段选择或继续编辑；重新生成整章也不能跳过比较。

### 4.3 DeepSeek 改写流程

任意叙述段可选择“更简洁／补充依据／统一表述／按要求改写”。上下文包含当前段、必要相邻段、关联证据、参数及规范快照；用户可查看本次发送范围。

返回建议稿、修改摘要、证据引用和待核项。参数、引用及数据块作为受保护节点；程序检查不可缺失、伪造或改值。自由文字仍须核查与证据是否相符，不能仅依赖 DeepSeek 自报“一致”。

采用建议前比对输入版本：若请求期间用户编辑了正文或参数，建议标为过期，不能直接覆盖。支持逐段采用、撤销和恢复历史稿。

沿用现有本地 DeepSeek 代理，新增章节生成与通用改写任务。官方支持 JSON Output，可启用后再做应用层字段与引用校验；有效 JSON 不等于事实正确。空响应、截断和超时保留旧稿并提供局部重试。[官方说明](https://api-docs.deepseek.com/guides/json_mode/)（`source_id: EXP-E07`）

## 5. 模型结果与规范协同

### 5.1 `.out` 是计算证据，不自动提供全部设计依据

当前上传入口明确支持 `WMASS.OUT / WZQ.OUT / WDISP.OUT`；用户所称“3D .out”按模型输出文件组设计，具体单文件格式仍需真实样本确认。

解析器按软件版本、文件头及内容特征识别格式，记录编码、解析覆盖率、未识别段落、工况、方向、楼层、单位、模型批次和行号。未知格式进入待解析，不能凭文件扩展名当作成功。

建筑图面、基础反力、配筋或专项计算若未包含在这些文件中，明确列为未提供；不能据此宣称已完成柱网逐层识别或基础承载验算。

结果表每行拆为“模型实际值／适用判据／判据来源和版本／计算判断／人工复核”。程序在输入、工况及适用规则齐全时算出通过或不通过；资料缺失或规则待核时显示无法判断。规则中的限值必须来自已确认的适用条款，不能沿用页面硬编码。已有反校核④复用同一份模型快照。

### 5.2 国标、行标、地标共用一份项目规范清单

②提供“设计依据”表；现有③地方规范模块负责地方资料发现、核查与推荐。两处共享项目规范清单的记录与版本，均通过统一服务提交修改，避免复制两套文本。

支持：检索添加、手动补录、排序、选择适用章节、修订项目备注、移出当前项目、查看原文及替代版本。

“修改”须区分项目备注与规范原文。项目备注可编辑；原文纠错形成带证据的新候选版本。“删除”表示移出本项目清单，保留审计，不删除规范库原件；已被正文引用时先显示影响。

每条记录至少包含：编号、名称、版本、发布/实施日期、有效状态、适用地区与条件、证据定位、核查日期、审核状态和本项目选择理由。目录级证据只能支撑“列入设计依据”；具体校核结论还需要条文级证据。

地区或设计基准日期改变时重新筛选；国标与地标有冲突时并列呈现，不简单采用“更严”或“更新”。人工确认项目采用规则后，影响相应的正文和校核。

### 5.3 腾讯 ima 接入方式

用户已确认“RMA”指腾讯 ima。拟采用：**ima 检索 → 本地服务整理证据 → 601候选/已核条款 → 603项目规范清单 → ②正文与③地方规范模块**。

- ima 用作资料获取与检索来源；库内有文件不等于已确认现行适用。
- 第一步验证只读检索、条目详情和原文定位能力，再决定是否能做条文级联动；不假定有密钥就具备所有权限。
- 若只能得到问答摘要或目录，先提供检索导航，不把摘要当作正式条文；可导入经确认的本地摘录作为替代证据。
- 连接凭据由本地服务处理，界面仅显示连接状态；不写入文档、前端、生成上下文或日志。
- 默认不向 ima 写回资料；无需把建筑和地勘原件上传到 ima。检索只发送所需规范编号、主题和适用条件。
- ima 暂不可用时，使用已有且适用性已确认的本地快照，并显示核查日期；不标为“实时最新”。

本次未读取密钥、未连接私人知识库；官方入口可定位，但可用接口、账号权限及原文返回能力仍待接入验证。`source_id: EXP-E08、SRC-EXP-IMA-20260927`。

## 6. 页面如何组织

保留现有②页及章节体系，增加以下工作区：

```text
当前项目 / 单体 / 修订版       生成初稿  更新受影响内容  校核  导出
资料：建筑 V…｜地勘 V…｜模型批次…｜参数 V…｜规范清单 V…
───────────────────────────────────────────────────────
章节目录与状态  │  正文编辑区                  │  按需打开的依据侧栏
概况            │  段落、表格、图片            │  当前段的原文与位置
设计依据        │  参数字段点选可回到来源      │  参数和规范版本
结构方案        │  编辑 / 改写 / 查看依据      │  采用理由与待核问题
基础……          │  新建议与人工稿差异          │  本次变更影响
───────────────────────────────────────────────────────
待确认事项：按“影响整章 / 影响局部 / 资料补充”排列
```

一般阅读时收起依据侧栏，正文保持清洁；需要校核时点段落定位证据。证据充分的正文正常成文，缺项集中显示，避免每段都堆满“请复核”。

草稿可导出，附带待核清单并明确草稿状态；存在关键冲突时不能签发。网页、Word和后续PPT读取同一正文版本、参数快照与可见章节集，不能分别再生成一遍。

## 7. 示例：结构选型这一段如何形成

以下仅演示写作机制，**不是本项目事实或设计结论**，`source_id: EXP-DEMO-001`，陈述类型：AI推断。

假设建筑提资明确“大空间使用、主要跨度”；①已确认采用某结构体系；当前模型提供对应单体的位移结果，但尚缺屋盖专项资料。

系统先准备：建筑功能与跨度的引用、①结构体系字段、模型结果及适用判据、屋盖缺项，再生成：

> 本单体主要承担【建筑功能】使用，主要跨度为【建筑资料字段】。统一技术措施确定采用【结构体系字段】。围绕大空间使用需求，结构布置需协调柱位与建筑净高；具体布置依据见【当前项目决定/图纸引用】。整体计算结果见表【自动引用】。屋盖专项资料尚未提供，该部分方案保留待定。

“满足功能、净高或规范要求”等肯定结论，必须另有相应证据；没有布置决定时不补造“已协调”。模型数据缺失或判据未核实时，也不增加“经计算满足”。

## 8. 落地顺序与验收

| 阶段 | 改造交付 | 完成标志 |
|---|---|---|
| 1：数据与联动 | 清除实际项目的示例回填；事实表、模型批次、参数绑定、版本记录 | 空项目不出现旧项目数值；人工稿不会被覆盖 |
| 2：生成与编辑 | 先贯通结构选型、基础方案、主要计算结果三节，再铺开其他章 | 三节能根据不同输入生成不同依据与内容，逐段编辑和改写可用 |
| 3：规范协同 | ②/③共用清单、601适用规则、ima只读适配与降级 | 改规范能定位受影响内容；未知状态不会进入正式结论 |
| 4：输出与回归 | 全章生成、签发快照、同源导出、跨项目盲测 | 新项目不带入历史专属事实，网页与导出一致 |

技术接入：保留主HTML入口与 `data-k/data-p` 映射；把候选事实、章节正文、参数引用和版本依赖放入独立模块，通过适配器渐进接入。现有 DOM 不再承担正式数据存储；603负责持久化，localStorage仅作恢复缓存。

建议最小数据对象：`ProjectSnapshot`、`EvidenceFact`、`ModelRun`、`ProjectRegulationSelection`、`WritingRule`、`SectionDraft`、`ReviewDecision`。模型返回的只能是章节草稿，不能直接写参数库或批准规范。

每次生成记录输入版本、规则/提示词版本、模型标识、请求时间、返回结果及采用记录；采用时检查项目、单体、段落和版本，拒绝过期请求写回。来源内容作为资料处理，不能作为执行指令。

必须通过的验收样例：

1. 空项目与仅上传一份资料：缺项明确，旧项目名称、尺寸、计算值均不出现。
2. “无转换梁”等否定、建议性表述和多单体混合输入：不升级成已确认事实。
3. 更换建筑功能/跨度或地勘条件：相关方案依据随之改变，无关人工段落保持。
4. 修改①参数：数字引用同步，关联叙述标记待核，已签发版本保持原样。
5. 改写等待期间再编辑正文：旧响应不能覆盖最新人工内容；拒绝擅自改参数。
6. 地勘建议与采用水位冲突：两值并列，不静默回填。
7. 模型跨批次混传、缺文件或解析失败：不拼接结果，不输出固定“满足”。
8. 结果超过已确认适用限值：输出不通过；缺限值则无法判断；X/Y方向分别核对。
9. 规范增删、地区变化或版本替代：①②③④受影响项可追溯，引用不悬空。
