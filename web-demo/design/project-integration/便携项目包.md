# 便携版项目包

source_id: USER-PORTABLE-20261030；原文事实：小香金猪要求同事各自本地使用，保留项目、图片、计算书 PDF 及参数联动。以下实现属于设计方案和验证记录。

## 使用

本地版“项目管理”提供“导出项目包”和“导入项目包”。导出先保存全部分区；保存冲突或导入、生成尚未结束时沿用原流程中止。导入始终建立新项目编号，成功后打开该副本，不覆盖原项目。

包为 `.workbench.zip`。包含全部已保存分区历史（正文、参数、已提取资料、图片、模型文本、人工表格值等）、当前计算书 PDF 清单中的真实文件及当前已联动 Excel 母件。历史快照内引用的已失效外部附件并不重新收集。原始 Word/Excel/PPT 文件若原流程只保存提取内容，包内不会声称包含那些从未保存的原件。

当前 PDF 缺失、已变化或不在普通目录时，导出失败并明确提示，不生成声称完整的空附件包。Excel 仅按现有 `jump-column`／`stair` 键从配置的 `CALCBOOK_SOURCE_DIR` 或本项目已导入母件目录收集；缺失或有多个同类文件时给出明确警告，不猜选。导入后 `portable-assets.calculationSources.missing` 必须作为计算书生成门槛，不能退回另一项目母件。

## 接入

- 服务：`server/portable-projects.mjs` 导出的 `portableProjectApi(env)`，注册到本地服务。
- 前端：引入 `portable-projects-ui.js`，仅在 `window.WORKBENCH_PORTABLE` 时显示。复用 `WorkbenchProjects.runOperation`／`openImported`，普通网页版行为不变。
- `POST /api/portable-projects/export?project=<32位项目ID>` 返回 ZIP，`X-Workbench-Warnings` 为 URI 编码的 JSON 警告数组。
- `POST /api/portable-projects/import` 以 ZIP 字节上传，返回 `{projectId,name,parts,pdfCount,warnings}`。
- 请求必须携带 `X-Workbench-Request: portable-projects` 并同源；不通过 GET 更改项目。
- ZIP 处理调用 `WORKBENCH_PYTHON`／`CALCBOOK_PYTHON` 的 Python 标准库 `zipfile`，无需额外压缩依赖。必须打包 `server/portable-archive.py`。

数据路径由服务根据项目 ID 构造：

| 内容 | 路径 |
|---|---|
| 分区与历史 | `WORKBENCH_PROJECT_STORE/<projectId>/<part>` |
| 导入 PDF | `CALCBOOK_UPLOAD_DIR/<projectId>/imported`（默认数据库根下 `calculation-uploads`） |
| 导入 Excel 母件 | `WORKBENCH_DATABASE_ROOT/project-assets/<projectId>/calculation-sources`；页面上传新版本使用其下独立批次目录 |
| 暂存 | `WORKBENCH_DATABASE_ROOT/.portable-tmp`；每次使用独立目录并清理 |

导入增加版本分区 `portable-assets`，记录原项目 ID、导出及导入日期、Excel 母件 SHA256 和缺失项。已有分区版本号保持不变，项目 ID 引用重映射。后续编辑继续使用原 `expectedRevision` 保护。

`server/portable-calculation-sources.mjs` 将计算书 status/workbook/export/template 接口接到该分区。前端 GET 请求携带 `project`，导出正文携带 `project_id`；项目切换时重新加载母件清单并清空旧表。导入项目的每个母件在使用前核验 SHA256；缺失、内容被改动、未登记文件或目录链接均明确失败，不回退全局母件。普通非 portable 版维持原母件选择行为。

## 本机选择 Excel 母件

计算书页提供“导入类型”和“选择本机 Excel”。当前只接受已实现的两类：跃层柱 XLSX 与楼梯 XLSM。`server/portable-calculation-upload.mjs` 注册 `POST /api/calculation-book/import-source?project=<id>&slot=<key>&revision=<assetsRevision>`，要求 `X-Workbench-Request: calculation-source` 与 URI 编码 `X-File-Name`；先核对真实格式，再只读检查可见工作表。单份最大 64 MB，宏和外部链接不执行。

上传后的母件在当前项目新批次目录保存，登记 `calculationSources.batch`。保存仍使用 `expectedRevision`，旧批次保留；失败只清理此次未登记批次。更换某类母件后，其旧网页编辑值保留在项目历史及 `edits` 的 `archived:` 项，不继续套入新母件，需重新联动。项目包同时收集已上传到项目的母件，即使尚未选择联动。

便携版对公式增加如下约束：

- 当前项目母件中的公式无有效缓存或有 Excel 错误值时，包含该表的导出失败，不把它输出为空白。
- 已保存缓存的未知公式只读显示；网页修改输入导致缓存可能失效时，拒绝导出并要求在 Excel 复算、保存后重新导入。
- 原跃层柱母件 B6/B8/B10 三个表达式完全匹配时，才按既有算法重算这三格；不能通过“文件名像跃层柱”给任意文件套固定算法。公式格不能被手工编辑值覆盖。
- 导出包含网页已显示的全部行列，不再额外截成 35 行、10 列；正文标明该表实际输出范围，未声称导出整份 Excel 全部工作表。

表达式核对来源（原文事实）：`E:/600-工作台数据库/610-待处理/01-计算书/跃层柱计算长度分析-ZYC.xlsx` 的“计算长度”工作表 B6、B8、B10；`source_id: LOCAL-CALC-JUMP-20261030`。仅只读核对表达式，未修改、复制原母件或带入历史数值；此核对不替代算法工程复核。

## 校验边界

每个包内文件在清单登记大小和 SHA256；读取时核查所有路径、文件类型、记录编号、版本及附件对应关系。拒绝目录穿越、盘符、反斜杠、链接、Windows 保留名、大小写重名、加密 ZIP、未知压缩方式、清单外文件或篡改。SHA256 用于传输完整性校验，不是来源签名。

限制：最多 6000 个 ZIP 文件、1 GB 解压总量、单文件 128 MB、单份项目 JSON 32 MB；当前计算书最多 200 份 PDF、总计 512 MB。全部校验在项目发布前完成；项目目录最后以新 ID 发布，失败不出现半个项目。原件只读。


合成数据只在忽略的 `qa/portable-projects`。覆盖三台电脑模拟目录往返、分区历史/人工正文/图片保留、PDF/Excel 字节一致及路径重建、同名编号不覆盖、损坏/越界/链接拒绝、母件缺失提示、主动同源请求。未使用正式项目和密钥。

`qa/portable-calculation-sources` 使用 openpyxl 生成内容不同的 A/B Excel 母件，通过真实 API 读取和生成 DOCX；检查生成正文只含当前项目值，缺项项目拒绝包含该 Excel 的导出，但仍可取得内置封面。前端模拟迟到失败，验证旧项目响应不能覆盖新项目状态。

母件上传回归包含实际格式预检、错误类型/非匹配算法拒绝、修订冲突、重新打包到另一数据目录仍可读取。`portable-formula-results.test.py` 验证已核对公式重算、未知公式无缓存拒绝、缓存失效拒绝、Excel 错误值拒绝、静态表不补造结果及最后可见单元格进入 DOCX。
