# 离线版文件兼容与准确度

来源：用户要求“同事操作简单、保证准确度，并完整识别 Word / Excel / PPT / PDF 多版本”（`source_id: USER-PORTABLE-FORMATS-20261030`，原文事实）。实现为文件预检和可追溯错误处理，不代表自动工程判断或所有 Office 环境均已通过实机验收。

## 两种版本分别显示

- **文件保存格式**：检查实际内容、容器目录、主文档声明及对应签名，不仅看扩展名。文件中的创建软件名称、AppVersion 是文件自报元数据，不作为当前电脑的软件安装版本。
- **本机软件版本**：仅读取固定 Word、Excel、PowerPoint、WPS、LibreOffice 程序注册路径及可执行文件版本。检测时不启动 Office、不打开用户资料、不读取许可证或凭据。`16.x` 不据此猜测为 Office 2016 / 2019 / 2021 / 2024 或 Microsoft 365。

## 当前识别范围与使用边界

| 类型 | 识别的保存格式 | 功能与边界 |
|---|---|---|
| Word | DOC / DOT 复合二进制（Word 97 起的受支持 nFib）；DOCX / DOCM / DOTX / DOTM；OOXML Transitional / Strict | 现代 XML 格式直接提取正文、表格和支持的图片。旧 DOC / DOT 仍通过本机 Microsoft Word 进行只读副本转换。宏不执行，外部链接不更新。缺图或不支持的图片明确提示并保留告警。 |
| Excel | XLS / XLT 的 BIFF5/7、BIFF8；XLSX / XLSM / XLTX / XLTM；XLSB | 预检后交给随包表格解析器。读取文件内已保存的值，不宣称已重新计算公式或宏。外部数据引用不更新。 |
| PPT | PPT / PPS / POT 二进制；PPTX / PPTM / PPSX / PPSM / POTX / POTM | 可识别文件实际类型与加密；现有工作台功能是按模板生成 PPTX，未新增任意历史 PPT 的全文导入。 |
| PDF | PDF 1.0–1.7、2.0；文件头及目录 `/Version` | 校验页树、页数和页面尺寸；加密、截断或损坏明确报错。格式识别不证明每页均有可提取文字；实际资料导入须逐页解析，无文字页单独提示，扫描图需 OCR。 |

RTF 冒充 DOC、HTML 冒充 XLS、任意 ZIP 冒充 DOCX、扩展名与实际类型不符均不静默导入。文件能被某个 Office 程序修复打开，不代表工作台应忽略结构损坏。对超出范围的格式给出“使用原软件另存标准副本”的提示，原文件不修改。

ZIP 检查包含重复项、危险内部路径、主文档关系、XML 外部实体声明、CRC、截断和解压上限。单文件上限 64 MB，展开内容上限 256 MB，最多 20000 项。CFB 检查 FAT / miniFAT 链、根目录、DOC 加密标志、XLS FilePass 和 PPT Current User 加密标志；Office 加密 OOXML 容器在解析前拒绝。PDF 用 pypdf 的严格模式检查页面结构。上述限额用于明确失败，不截断后继续生成报告。

## 接口与依赖

- `server/document-format-api.mjs` 导出 `documentFormatApi(env)`。
- `POST /api/portable/formats`：原始文件字节；`X-Workbench-Request: portable-formats`，`X-File-Name: encodeURIComponent(filename)`。返回 `{detected}`；结构错误、加密或伪装类型返回 422 并带 `code`，组件不可用返回 503，超上限返回 413。
- `GET /api/portable/capabilities`：返回 `installedApps`、`components`、`features`、`versionNote`。可用检测仅是运行条件检测，实际转换结果另行校验。
- Python 识别器需要标准库与 `pypdf`；Word 提取还需要 `lxml`、`Pillow`。Word 生成使用 `python-docx`，计算书 Excel 使用 `openpyxl`。工作台服务配置 `WORKBENCH_PYTHON`，避免依赖开发电脑路径。

## 验证

在 `web-demo` 运行：

```powershell
node --test design/project-integration/document-format.test.mjs design/project-integration/intake.test.mjs design/project-integration/legacy-doc.test.mjs
& <文档Python路径> design/project-integration/document-format.test.py
```

测试覆盖全部 15 种 OOXML 内容类型、现代文档与旧复合文件、miniFAT、加密和损坏拒绝、PDF 多版本与目录版本覆盖；使用真实文档库生成 DOCX / XLSX / PPTX 检查，并核对 Word Strict / Transitional 的文本、数值和表格不变。合成文件不是工程事实来源；不把这些测试解释为所有历史 Office 或 WPS 版本均已实测通过。

2026-10-30 本机检测到 Word / Excel / PowerPoint 程序版本 `16.0.20527.20088` 及自动化注册；WPS / LibreOffice 未检测到。额外的 Office COM 生成旧格式样本在 Word 阶段未完成，已停止该隔离脚本，因此本次不把真实旧格式 Office 转换计为通过。17 组 Python 文件格式测试和 17 项 Node / 既有资料提取回归通过；上述现代 DOCX / XLSX / PPTX 为文档库实际生成文件，旧 CFB 用合成结构验证。

经开项目用户已指定的地勘 DOC 和建筑 DOCX 做了只读格式复核：DOC 正确识别到 `nFib=0x00C1`、`nFibNew=0x010C`，并提示非完整尾扇区；DOCX 正确识别为 Transitional，外部引用不更新。此项仅验证新预检没有错误阻断既有样本，未重新运行它们的全文转换；原件未修改、未打包。另经服务端真实调用，合成 DOCX 的 `23.70 m / 5 / 1234.56 m2` 及表格值保持不变，合成两页 PDF 的页数识别为 2。

## 格式规则来源

以下为原文事实（文件格式规则），只用于文件识别，不是结构设计规范：

- `source_id: MS-DOC-FIBBASE`：[Microsoft MS-DOC FibBase](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/26fb6c06-4e5c-4778-ab4e-edbf26a545bb)，wIdent、nFib、fDot、fEncrypted、fWhichTblStm。保留 nFib 及存在时的 nFibNew 原始值，不将其解释为安装软件年代；nFib 可以被文件后部 nFibNew 替代。
- `source_id: MS-XLS-ENCRYPTION`：[Microsoft MS-XLS Encryption](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/0f2ea0a1-9fc8-468d-97aa-9d333b72d106)，FilePass 标志及未加密的记录头。
- `source_id: MS-PPT-CURRENTUSER`：[Microsoft MS-PPT CurrentUserAtom](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-ppt/940d5700-e4d7-4fc0-ab48-fed5dbc48bc1)，headerToken、docFileVersion。
