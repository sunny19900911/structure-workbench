# 小黑箱核心参数接入

source_id: USER-BLACKBOX-PARAMETERS-20261110；实现映射为AI推断，以下测试为实际观察。

入口仍为 `web-demo/启动小黑箱.cmd`，主屏新增折叠“核心参数”。保持原业务页面打开，参数读写经同一个浏览器业务队列执行，没有独立参数库。

| 分组 | 原数据/写入路径 |
|---|---|
| 项目 | project_name、project_code、region、struct_sys；仅显示原网页已有控件与参数键 |
| 抗震 | intensity、pga、eq_group、site_class、seismic_cat、damping |
| 荷载 | wind、snow、snow_zone、wind_shape、wind_rough |
| 材料与等级 | safety、foundation、pile、anti_float、waterproof、fire、wall_drydensity、wall_abs |
| 单体采用 | 当前单体已有confirmed的struct_sys、site_class、water_depth事实；附source_id |
| 原表 | concrete、durability、floor、roof、equipment，保留原表头和单位 |

公共值走原 `measures.update`，规范化、衍生值与文稿联动仍由 `L.adoptParameters/publish` 管理；单体事实走 `intake.adopt`，人工更正记录原值和来源；表格走 `measures.table`，参数联动格仍由原接口拒绝直接改写。空值、选项与单位沿用原控件。逐项提交当前context的expectedRevisions，不绕过角色、签发或冲突保护。保存后重新读回参数版本。项目切换清空旧编辑控件，服务器再次验证当前目录关联的projectId。

`parameters.read`为新增只读业务操作，自动映射为MCP工具 `workbench_parameters_read`，与小窗口读取相同schema和值。参数请求取消会传入bridge的AbortSignal；排队任务作废，执行中仍沿用OUTCOME_UNKNOWN语义，不自动重试。

单体几何来自当前建筑资料，分列规划、消防、建筑、结构、抗震高度及明确存在的高差、绝对标高，均为只读资料。没有新建几何采用参数状态，也没有将seismic查表条件当作采用值。尚未有统一写入映射的几何项不能宣称支持编辑；缺项不猜值。

## 参数入口更正（2026-11-10，覆盖上面的独立表单方案）

用户明确要求复用原统一技术措施输入页。小黑箱只保留“核心参数”按钮，打开同项目的原工作台并指定view=measures；原页面负责填写、保存和联动。小窗口不再另列字段、不再维护草稿、不再自动启动隐藏业务页。MCP仍读取同一项目采用数据，无需“导回”或重复录入。旧自动表单测试属于被替代版本的历史验证，不作为当前交互验收；当前验收见parameter-navigation-qa.mjs。
