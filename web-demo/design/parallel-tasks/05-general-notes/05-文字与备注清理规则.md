# 文字与备注清理规则

机器可读草案保存于604：`rules/general-note-cleaning-rules.v0.1.draft.json`。

## 1. 先分类，再清理

每个内容块必须先被赋予 `content_role`，并保留 `source_id` 与原定位：

| `content_role` | 含义 | 正式输出默认 |
|---|---|---|
| `editorial_note` | 模板编制注释、编制方法、转CAD提示 | 不输出正文，保留审计 |
| `mixed_annotation` | 同一提取块内同时存在正式文字和 `【注释】` | 整块暂不进入正文，进入逐项拆分队列 |
| `designer_prompt` | 要点、提醒、待设计人员处理事项 | 进入复核队列 |
| `formal_text` | 正式出图文字 | 输出 |
| `project_placeholder` | XXX、待填值、项目占位符 | 替换后输出；未替换阻断 |
| `optional_clause` | 备用、选项、条件性章节 | 由特征规则/人工决定 |
| `example_text` | 示例值/示例写法 | 替换或确认后方可输出 |
| `coordination_item` | 待协、跨专业责任 | 必须人工关闭 |

颜色、字体、底纹只能作为识别线索，不能单独决定删除。

## 2. 三档处理

### A. 自动清理（低风险，可审计）

- 用户于2026-09-25明确批准：已由604母版显式标记为 `editorial_note` 的纯编制说明、操作提示、目录转换提示，从派生正文草案中自动省略；原始母件不修改。对应规则 `GN-C-001`。
- 系统生成目录时，不把母版中的编制用目录文本重复输出；原文仍保存在来源层。
- 已完成占位符替换后，移除纯占位符控制标记，但不改变替换后的正式文字。

自动清理必须记录规则ID、原文摘要、来源和输出快照；不允许用正则把所有方括号内容一律删除。

### B. 建议清理（低/中风险，可整组确认）

- `【要点】`、`【示例】`、`【备用】` 等已被语义分类、但尚未获公共规则批准的块。
- 与已批准项目特征明显不相符的备用章节。
- 经③确认不适用/失效的地方标准引用。
- 编辑色文字在语义标注已确认的情况下统一转为正式样式或排除。

整组确认需同一规则、同一风险等级、无依赖冲突，并逐条展示修改前后。

### C. 必须人工确认/阻断

- `mixed_annotation`：旧版DOC复杂表格可能把正式文字与 `【注释】` 压入同一提取块。系统必须整块隔离、保留 `block_id/source_id/source_locator`，不得猜测注释终点或静默删除；结构化拆分后再决定正式文字是否回填。
- `【待协】`、责任界面、专项设计范围、强制性/安全相关内容。
- 互斥 `【选项】` 的选择，除非唯一选择已由批准参数和批准规则确定。
- 所有 `XXX/XXXX/待填写/SRC-PENDING`、空参数、未确认规范。
- 自动识别置信度不足、颜色语义不明确、跨专业冲突、来源版本冲突。
- 历史项目中的项目专属文字拟复用到新项目。

## 3. 输出前阻断检查

1. 正文无未解析占位符或编制标记。
2. 所有可见条款均有 `clause_id` 和 `source_id`。
3. 所有删除/覆盖决定均有规则或人工理由。
4. 所有规范引用均来自③的已确认清单。
5. 预览和Word导出使用同一 `output_snapshot_id`。
6. 审签锁定后，参数或规则版本变化会令旧签名失效并生成差异。
