# 产品主线：从“功能集合”到“项目参数决策闭环”

## 1. 产品定位

沿用既有产品名称：**结构与技术措施·一体化工作台**。正式入口固定为 `web-demo/workbuddy-integrated-studio.html`，不另起产品名、首页或导航。`source_id: SRC-P01-007, SRC-P01-014`【原文事实】

一句话定位：在既有①—⑧模块骨架内，为结构设计项目建立一套经工程师确认的参数基准，使参数有来源、冲突有去处、成果可复用、模型能反校核、负责人可签发。`source_id: SRC-P01-001, SRC-P01-007, SRC-P01-014`【我的观点】

领导汇报时不宜把“AI”作为主语。AI 的作用是提取、归类、对照和生成候选内容；工程师负责关键参数确认，专业负责人负责复核和签发。`source_id: SRC-P01-001, SRC-P01-004, SRC-P01-008, SRC-P01-010`【我的观点】

### 产品边界

| 工作台负责 | 工作台不负责 |
|---|---|
| 汇集来源、抽取候选、暴露冲突 | 自动裁决多来源冲突 |
| 记录人工确认和适用范围 | 替代设计人员的专业判断 |
| 用统一参数生成工作草案 | 把草案自动视为正式成果 |
| 对照模型与措施并报告差异 | 未经确认自动修改模型或参数 |
| 形成可复核、可量化的过程证据 | 在未建真实权限前承诺审计合规 |

`source_id: SRC-P01-001, SRC-P01-004, SRC-P01-007, SRC-P01-010`【我的观点】

## 2. 核心价值

### 价值一：减少重复录入

同一批确认参数应被统一技术措施、扩初说明、汇报卡和反校核共同使用，避免在多个 Word、表格和模型界面反复抄写。`source_id: SRC-P01-007, SRC-P01-009`【原文事实 + 我的观点】

### 价值二：把冲突显性化

工作台最有价值的输出不只是“正确值”，还包括“哪些值尚不能确定、为什么、由谁确认”。候选值、来源和确认记录等经过独立验证的交互，应作为①/②中的子卡或全局受控抽屉接入，不得保留为另一套正式工作台。`source_id: SRC-P01-003, SRC-P01-004, SRC-P01-014`【我的观点】

### 价值三：让负责人抽查更快

负责人应从既有首页模块状态进入①的关键参数摘要和④的差异清单，必要时再下钻来源证据，而不是另开一个“领导驾驶舱”或先阅读整份长文档。`source_id: SRC-P01-007, SRC-P01-014`【我的观点】

### 价值四：让成果进入现有生产习惯

输出仍以网页、Word、PDF、JSON 等现有可接受形式交付；AI 只在过程中辅助，不改变“工程师复核后签发”的责任链。`source_id: SRC-P01-002, SRC-P01-013`【原文事实 + 我的观点】

### 价值五：积累可复用的组织经验

统一措施、问题项、确认记录和反校核规则一旦结构化，才可能跨项目复用；但外部项目数值只能作为参考，不能静默成为当前项目事实。`source_id: SRC-P01-001, SRC-P01-006, SRC-P01-009`【我的观点】

## 3. 典型用户

| 角色 | 核心任务 | 当前痛点 | 工作台提供的最小价值 | 不应强迫其承担的工作 |
|---|---|---|---|---|
| 普通设计人员 | 整理输入、确定项目参数、生成草案、核对模型 | 资料散、重复抄、冲突发现晚 | 候选参数、证据定位、一处确认、多处复用、差异清单 | 维护全院标准库、手工填管理报表 |
| 专业负责人 | 复核关键口径、退回问题、签发阶段成果 | 审核入口分散、很难追溯“为何这样定” | 风险优先清单、来源下钻、确认理由、签发门槛 | 逐页重做设计人员的资料整理 |
| 管理者/全院总控 | 看项目状态、风险、指标与试点收益 | 只能听汇报，缺少统一口径和量化证据 | 项目快照、阶段分布、异常提示、试点数据 | 浏览项目全部明细或直接修改技术参数 |

## 4. 既有骨架中的产品主线

正式黄金路径不重组导航，而是在现有模块间行进：

1. **首页卡片墙**：选择项目、角色和阶段，查看①—⑧卡片状态。
2. **①统一技术措施**：维护公共参数唯一真源、显式结构特征开关和适用章节集；候选来源与人工确认能力在该卡内增量接入。
3. **②结构扩初说明**：单向继承①，补充建筑、地勘、模型结果，并用同一可见章节集生成网页/Word/PPT。
4. **④反校核**：导入模型实际参数，与①逐项比较，只报告差异和建议。
5. **既有状态机**：设计人员提交，专业负责人审核/退回/签发；已签发模块保持只读。
6. **⑤与⑥**：⑤形成单体统计和项目快照，⑥只读汇总多个项目快照。
7. **③、⑦、⑧按场景进入**：③服务地点规范与601，⑦在既有卡内消费603/604，⑧保留目录即台账。

`source_id: SRC-P01-007, SRC-P01-014, SRC-P01-015, SRC-P01-016`【我的观点】

领导演示聚焦“首页→①→②→④→⑥”，但首页仍完整保留八张模块卡；其余卡不是被删除或另建，而是在路线图中说明成熟度和接入顺序。`source_id: SRC-P01-014`【我的观点】

## 5. ①—⑧模块产品定位

| 模块卡 | 产品职责 | 本轮规划重点 |
|---|---|---|
| ①统一技术措施 | 公共参数唯一真源、特征开关、章卡/子卡、网页/Word | 恢复并验证 WorkBuddy 章卡机制；接入来源与人工确认，不复制参数 |
| ②结构扩初说明 | 继承①，补充建筑/地勘/模型结果，生成成果 | 验证参数继承、可见章节集和网页/Word/PPT一致 |
| ③整理地方规范 | 地点识别、601查询、联网候选、人工确认 | 接入任务二成果，不交付独立规范站点 |
| ④反校核 | 模型实际值与①约定值比较 | 固定黄金样例；只报差异，不静默改值 |
| ⑤用钢量统计 | 单体导入与统一口径统计 | 真实项目验证输入兼容，并为⑥提供快照 |

### 当前阻碍产品可信度的五个问题

1. **当前运行分支尚未完整保留功能基线。** 章卡、小节子卡、`SECMETA/SUBRULES/FEATKEYS` 和结构特征开关需要从 WorkBuddy 基线逐项迁入，不能整体覆盖。`source_id: SRC-P01-014, SRC-P01-016`【原文事实】
2. **验证能力尚未正式接入。** React 参数追溯/人工确认等交互有价值，但没有落到①/②或全局受控能力中。`source_id: SRC-P01-003, SRC-P01-004, SRC-P01-014`【AI推断】
3. **正式项目真源尚未统一进入603。** 当前 localStorage 可保存界面状态，但正式参数版本、人工决定和输出版本最终必须进入603。`source_id: SRC-P01-014`【原文事实】
4. **卡片化最危险的风险是内容静默丢失。** 已有基线曾出现H2标题丢失，后续每次迁入都必须验证章节、目录和导出一致性。`source_id: SRC-P01-016`【原文事实】
5. **功能成熟度不同但模块编号不能被破坏。** ⑦仍是占位，③⑤⑥⑧仍需真实项目验证；处理方式应是状态和路线图说明，不是删除卡片或建立替代导航。`source_id: SRC-P01-007, SRC-P01-014`【我的观点】

## 7. 北极星指标与阶段指标

### 北极星指标

**每个试点项目中，经负责人确认且能定位来源、驱动成果、通过反校核的关键参数比例。**`source_id: SRC-P01-001, SRC-P01-004, SRC-P01-007`【我的观点】

建议定义：

`闭环参数率 = 已确认且有来源且被成果引用且完成反校核的关键参数数 / 纳入试点的关键参数总数`

这比“生成了多少文字”更接近业务价值，也能同时约束准确性、追溯性和落地使用。`source_id: SRC-P01-008`【我的观点】

### 试点阶段配套指标

- 关键参数来源可定位率。
- 待确认项在签发前的处置完成率。
- 同一参数跨成果一致率。
- Word/PDF/JSON 输出成功率。
- 从资料齐备到可校审初稿的实际用时。
- 系统提前发现的冲突、缺项和版本问题数。
- 新用户完成黄金路径的独立完成率。
- 愿意在下一个项目继续使用的试点用户比例。

`source_id: SRC-P01-008`【作者观点 + 我的观点】

## 8. 产品原则

1. **参数优先于文档**：先确认参数，再生成长文档。
2. **问题优先于美化**：未解决冲突必须醒目，不能用顺滑文案掩盖。
3. **人工确认是能力，不是缺陷**：把关键判断留痕，才有工程可信度。
4. **签发前可追溯，签发后可复现**：任何正式采用值都能回到来源和决定记录。
5. **管理视图只读汇总**：管理者看状态与异常，不直接修改项目技术参数。
6. **先真实试点，再扩大功能**：没有实测收益，不承诺全院推广。
7. **增量接入，不另建成品**：独立原型只验证交互或算法，正式能力必须回到①—⑧或后台服务。
8. **隐藏不删除，网页与导出同源**：条件卡不可见时数据仍保留，导出只消费同一可见章节快照。
