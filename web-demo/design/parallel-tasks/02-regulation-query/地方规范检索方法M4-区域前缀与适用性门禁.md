# 地方规范检索方法 M4：区域前缀与适用性门禁

更新时间：2026-09-26  
适用范围：任务二地方规范候选发现、适用性判断、状态核验和主工作台回写。  
上位方法：`地方规范检索方法M3-项目反查与版本闭环.md`。  
本轮项目基准：`SRC-610-HISTORY-PROJECTS`（610 新增历史项目总说明，只读）。

## 1. 本轮新增认识

历史项目总说明不是“现行规范目录”，而是某个项目在某个时间点引用过的资料集合。它可以帮助发现漏项，但不能整表导入工作台。本轮样本同时出现了以下五种情况：

1. 真实的新候选：浙江、江苏及雄安新区的工程建设标准；
2. 编号或标题抄写异常：河北条目写成 `DB15(J)/140-2012`，与河北 `DB13` 区域前缀不符；
3. 跨区域模板残留：江阴项目引用南京市图审技术措施，浙江项目材料中又出现上海、北京文件；
4. 文件类型混杂：标准、条例、厅级导则、图集、规划纲要被放在同一清单；
5. 时间截面滞后：历史项目未包含其后发布的 `DB1331/T 109-2025《雄安新区建设工程抗震设防标准》`。

因此，项目反查之后必须增加“区域、适用性、类型、时间、状态”五道门禁。

## 2. 五道门禁

### 2.1 区域前缀门禁

先核对标准编号与项目行政区是否一致。当前与本轮有关的前缀为：

| 前缀 | 地区 | 使用规则 |
|---|---|---|
| `DB13` / `DB13(J)` | 河北省 | 河北项目候选 |
| `DB1331` | 雄安新区 | 雄安专项候选，不能只扫河北省目录 |
| `DB15` | 内蒙古自治区 | 出现在河北项目中时必须先判为编号异常或跨区引用 |
| `DB32` / `DGJ32` | 江苏省 | 江苏省级候选 |
| `DB33` / `DBJ33` | 浙江省 | 浙江省级候选 |

前缀冲突不自动改号。系统应保存原始写法，另设“建议归一写法”，经权威源确认后再回写。

### 2.2 适用区域门禁

按“项目所在地 → 省级规则 → 地市规则 → 新区/功能区专项规则”逐层判断：

- 江阴项目不能因为设计说明中出现《南京市图审中心统一技术措施》，就把它作为江阴默认适用规范；
- 浙江项目材料中出现上海、北京管理文件，只能视为跨区参考或模板残留；
- 雄安项目必须同时检索河北省和 `DB1331` 雄安新区专项标准，两条线不能互相替代。

凡跨省、跨市引用，必须提供明确的合同、批复、审查要求或文件自身适用范围，才能升格为“项目适用”。

### 2.3 文件类型门禁

查询结果默认只展示“工程建设标准/地方标准”；其他资料保留在候选库，但不混入同一现行规范列表：

| 类型 | 默认是否进入规范列表 | 处理方式 |
|---|---:|---|
| DB/DBJ/DGJ 工程建设标准 | 是 | 核验状态后展示 |
| 法规、条例、政府令 | 否 | 单列“法规依据” |
| 厅级导则、技术要点 | 否 | 单列“专项规定” |
| 标准设计图集 | 否 | 单列“图集” |
| 规划纲要、发展规划 | 否 | 单列“规划依据”，不得标成技术规范 |
| 内部统一措施、图审口径 | 否 | 仅在适用单位和地域明确时展示 |

### 2.4 时间门禁

历史项目清单只证明“当时引用”。每次查询还要以核查日重新扫描：

1. 项目文件成文日期之后发布的新标准；
2. 同名、同编号族的新年份版本；
3. 发布公告中的实施日期和旧版废止条款；
4. 新区独立编号体系中新发布的专项标准。

本轮用该规则反查出历史项目未列的 `DB1331/T 109-2025《雄安新区建设工程抗震设防标准》`，全国标准信息公共服务平台显示其为现行，发布日期 2025-03-18、实施日期 2025-05-14。

### 2.5 状态门禁

状态至少分四级：

- `已核实-现行`：权威状态平台或主管部门现行目录明确；
- `已核实-非现行`：权威废止/替代公告明确；
- `待核实-存在`：权威正文、发布页或后续官方引用能证明文件存在，但不足以判定核查日状态；
- `待纠错`：名称、编号、地域或版本存在冲突。

第三方出版库的“现行/废止”与政府网页冲突时，不做多数表决；保留冲突并等待主管部门状态页或清理公告。

## 3. 新的检索流程

1. 从历史项目逐条抽取原始名称、原始编号、引用位置、项目地点和项目日期；
2. 做区域前缀校验，生成编号异常清单；
3. 做项目所在地校验，隔离跨省、跨市引用；
4. 按标准、法规、导则、图集、规划、内部措施分类；
5. 以省级目录和新区独立目录双线枚举，补查项目日期之后的新文件；
6. 对每个标准建立“发布—实施—替代—废止”版本链；
7. 只有通过适用性和状态门禁的记录才进入主工作台；其余留在候选/人工确认流程。

## 4. 机器校验规则建议

建议 601 候选接口增加以下可计算规则；这是字段/API需求，不直接修改 601：

- `raw_code`：项目资料中的原始编号；
- `normalized_code`：经权威源核准后的编号；
- `region_prefix_match`：编号前缀是否与项目行政区匹配；
- `applicability_scope`：省/市/新区/项目/参考；
- `document_type`：standard/regulation/guideline/atlas/plan/internal_measure；
- `project_reference_date`：历史项目引用日期；
- `official_status_as_of`：状态核验日期；
- `status_conflict`：不同来源是否存在状态冲突；
- `introduced_after_project`：是否晚于历史项目成文日期；
- `candidate_reason`：进入候选或被隔离的原因；
- `source_id`、`source_url`：可追溯证据。

## 5. 本轮验证结果

- 浙江：发现工作台未收录的结构抗震性能化标准、墙板/砌块规程、超限导则等候选；其中 `DB33/T1027` 的完整编号应继续按权威正文归一为 `DB33/T1027-2018`。
- 江苏：`DB32/T 4399-2022` 已由全国标准信息公共服务平台确认为现行；南京图审技术措施不自动适用于江阴。
- 河北/雄安：历史项目条目存在明显编号异常；同时必须新增 `DB1331` 专项目录扫描，不能只查 `DB13`。
- 历史 Word 的正文条目数与末尾汇总口径不完全一致，抽取时必须以逐条正文为准，汇总表只作校验线索。

## 6. 回写边界

本轮只更新方法和候选学习台账，没有修改 601 核心文件，也没有把待纠错或待核实条目写入主工作台正式结果。正式回写前仍需逐条人工确认。
