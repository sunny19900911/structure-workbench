# 601 字段与 API 需求

本文件只向 601 主任务提出契约，不规定其文件夹结构、数据库引擎或内部实现。`source_id: SRC-T2-DESIGN-001`，陈述类型：我的观点。

## 1. 概念实体

### 1.1 `place`

必需字段：

```text
place_id, official_name, place_type, admin_code,
parent_place_ids[], valid_from, valid_to,
source_id, locator, review_status
```

`place_type` 至少区分：省级、地市级、区县级、乡镇级、开发区/功能区、气象站、地址点。

### 1.2 `place_alias`

```text
alias_id, alias_name, normalized_name, alias_kind,
place_id, parent_hint_ids[], valid_from, valid_to,
source_id, locator, review_status
```

别名不得只有字符串映射；必须能解释何时、为何、基于什么来源映射。

### 1.3 `place_relation`

```text
relation_id, from_place_id, to_place_id, relation_type,
coverage_note, valid_from, valid_to,
source_id, locator, review_status
```

`relation_type`：`admin_parent / located_within / overlaps / managed_by / historical_alias_of / informal_alias_of`。

### 1.4 `document`

```text
document_id, title, document_no, document_level, document_kind,
issuer, publication_date, implementation_date, repeal_date,
replaced_by_ids[], replaces_ids[], jurisdiction_place_ids[],
lifecycle_status, effective_status, authenticity_level,
source_id, source_url, acquired_at, media_type, source_hash,
review_status, reviewed_by, reviewed_at, review_note
```

三个状态不得混用：

- `lifecycle_status`：discovered / downloaded / extracted / reviewed / archived；
- `effective_status`：not_yet_effective / effective / repealed / superseded / unknown；
- `review_status`：candidate / pending_first_review / pending_final_review / approved_formal / rejected。

### 1.5 `claim`

```text
claim_id, document_id, parameter_key, value, unit,
claim_text, claim_type, locator,
scope_place_ids[], scope_relation_ids[], project_conditions{},
valid_from, valid_to, extraction_method,
review_status, reviewed_by, reviewed_at,
source_id, conflict_ids[]
```

`claim_type` 必须使用项目约定：原文事实 / 作者观点 / 我的观点 / AI推断。只有“原文事实”且正式复核通过的 claim 才能进入正式参数候选。

### 1.6 `conflict`

```text
conflict_id, conflict_type, claim_ids[], place_scope_ids[],
parameter_key, detected_at, status,
resolution_note, resolved_by, resolved_at, resolution_source_ids[]
```

601 保存规范库层面的冲突与解决；项目选择写 603，不写回通用 claim。

### 1.7 `review_event`

```text
event_id, object_type, object_id, action,
from_status, to_status, actor_id, actor_role, happened_at,
note, evidence_source_ids[], object_version
```

正式晋升、驳回、标废、恢复和替代关系变化都必须有事件，不能只覆盖当前字段。

## 2. 状态计算

以请求 `as_of_date` 为基准：

```text
implementation_date > as_of_date                       => not_yet_effective
repeal_date <= as_of_date                               => repealed
approved successor implementation_date <= as_of_date    => superseded
implementation_date <= as_of_date 且未到 repeal_date     => effective
缺关键日期或状态证据                                    => unknown
```

网页发现状态不得直接参与上述“正式”计算。候选资料可以显示候选状态，但 `review_status != approved_formal` 时 `adoptable=false`。

## 3. API 契约

### 3.1 地点解析

`POST /api/601/places/resolve`

请求：

```json
{
  "query": "天津临港新区",
  "parent_place_ids": [],
  "address_hint": "",
  "as_of_date": "2026-09-25",
  "limit": 10
}
```

响应关键字段：

```json
{
  "resolution_id": "RES-...",
  "state": "resolved_needs_confirmation",
  "normalized_query": "天津临港新区",
  "candidates": [{
    "place_id": "...",
    "display_path": "天津市 / 滨海新区 / 临港功能区",
    "place_type": "development_zone",
    "score": 0.86,
    "matched_by": "development_zone_alias",
    "relation_ids": ["REL-..."],
    "source_id": "SRC-...",
    "locator": "...",
    "review_status": "pending_final_review",
    "why_not_auto": ["功能区不是法定区县", "关系证据尚未批准"]
  }]
}
```

要求：同一数据版本和相同请求返回稳定排序；每个候选必须带匹配解释，不只给相似度。

### 3.2 规范查询

`GET /api/601/query?place_id=...&as_of=2026-09-25&parameter_keys=intensity,pga,eq_group,wind,snow&include_candidates=false`

响应：

```json
{
  "query_id": "RQ-...",
  "data_version": "601-2026.09.25.1",
  "place": {"place_id": "...", "display_path": "...", "confirmed": true},
  "as_of_date": "2026-09-25",
  "groups": {
    "national": [],
    "local": [],
    "special": [],
    "project_reference": []
  },
  "conflicts": [],
  "coverage": {
    "local_search_completed": true,
    "message": "未检索到不等于不存在"
  }
}
```

每条结果必须包含：`claim_id / parameter_key / value / unit / scope_match / effective_status / review_status / publication_date / implementation_date / repeal_date / source_id / locator / source_hash / claim_type / conflict_ids / adoptable`。

### 3.3 候选资料写入

`POST /api/601/candidates`

允许来源：③上传/OCR、官方网页发现、人工登记。响应返回 `candidate_id`，初态恒为 `candidate`；客户端不得传 `approved_formal`。

### 3.4 人工复核与正式晋升

`POST /api/601/reviews`

```json
{
  "object_type": "document",
  "object_id": "DOC-...",
  "decision": "approve_formal",
  "expected_version": 3,
  "reviewer_note": "已核对发布机关、正式正文、实施日期和条文定位",
  "evidence_source_ids": ["SRC-..."]
}
```

要求：

- 基于 `expected_version` 乐观锁；
- 服务端验证角色、必填证据和状态跃迁；
- 返回新的对象版本与 review_event；
- 候选晋升后旧版本仍可查询。

### 3.5 证据读取

`GET /api/601/evidence/{source_id}?locator=...`

返回元数据、允许显示的短摘录、定位信息、哈希与原件打开方式。不得让 DeepSeek通过自由路径读取任意文件。

## 4. ③写 601、①写 603 的边界

| 动作 | 写入位置 | 说明 |
|---|---|---|
| OCR/网页发现一个规范 | 601 候选 | 不能成为正式参数 |
| 人工核验文档真伪、日期、替代关系 | 601 review_event | 影响全库 |
| 人工核验条文与结构化参数 | 601 claim/review_event | 影响全库 |
| ③查询某项目适用候选 | 不写或写查询日志 | 查询结果不等于采用 |
| ③“送到①待确认” | 603 candidate_bundle | 项目级暂存 |
| ①确认采用某候选 | 603 decision + 参数版本 | 改写既有参数真源 |
| ①拒绝候选 | 603 decision | 不影响 601 的通用有效性 |

## 5. 错误码与前端行为

| code | 前端行为 |
|---|---|
| `PLACE_AMBIGUOUS` | 显示候选并阻止规范查询 |
| `PLACE_UNRESOLVED` | 提示补充省市/地址，不回退到模糊首项 |
| `SCOPE_UNCONFIRMED` | 展示规则但 `adoptable=false` |
| `EVIDENCE_INCOMPLETE` | 标“待核实”，不能晋升 |
| `CONFLICT_OPEN` | 并列冲突值，跳转③处理 |
| `DOCUMENT_NOT_EFFECTIVE` | 显示日期原因，禁用采用 |
| `VERSION_CONFLICT` | 刷新对象，保留用户未提交意见 |
| `ROLE_FORBIDDEN` | 沿用工作台角色提示，不创建新角色 |
| `CARD_LOCKED` | 提示按现有流程撤回签发 |
