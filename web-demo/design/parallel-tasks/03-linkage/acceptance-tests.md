# 接入验收用例

## A. 编号与撤销

1. 删除 `3.2.2` 后，同章节后续可见条款变为 `3.2.2…N`，无断号；稳定 uid 不变。
2. 撤销删除后，原顺序、决定、理由和编号全部恢复。
3. 新增项目条款后生成新的项目级 uid，写603，不写604；同章节编号连续。
4. 拖拽改变顺序后显示号重算；交叉引用仍指向 uid，预览文本引用号同步更新。
5. 重做与版本回退均调用同一编号函数，结果确定性一致。
6. 隐藏/删除的数据仍可恢复，未物理丢失。

## B. 参数联动

1. ①修改参数只触发一条参数版本和影响事件，不产生第二个可编辑真源。
2. ②纯参数引用实时更新；条件显隐和脱链固化内容只提示复核。
3. ④既有 `RCLAST` 标过期，必须重新 `rcStart()`；系统不自动执行 `rcAdopt()`。
4. ⑦只重算规则建议，不覆盖已有 `human_decision`。
5. PPT受影响页来自②的可见集/参数引用矩阵，不单独维护参数副本。

## C. 总说明规则与人工复核

1. 规则建议可由相同参数版本和规则版本重复算出相同结果。
2. AI建议不能写入 `human_decision` 或直接提交/签发。
3. 人工决定覆盖规则建议时必须填写理由、人员、角色和时间。
4. 多来源冲突全部保留为问题项；不能静默选择。
5. 每条可复用结论具有 `source_id`；缺失时显示“待核实”。

## D. 依赖、快照与导出

1. 删除仍被其他条款/成果引用的条款时，依赖检查返回 blocker。
2. 存在 `review`、理由缺失、604未发布版本或参数版本漂移时不能签发。
3. 页面预览和 Word 导出记录相同 `snapshot_id`、条款 uid 列表和编号映射。
4. Word 不出现页面已删除的条款，页面也不遗漏 Word 中的条款。
5. 参数或决定变化后，旧 `visible_set_snapshot` 标过期，不能继续导出为新版本。

## E. 角色、阶段与状态机

1. 施工图阶段才显示⑦；无权限角色仍由 `cardVisible()` 隐藏。
2. 设计人员按 `CARDS.c7.roles.d='填'` 提交；专业负责人按 `roles.m='审'` 审核。
3. `CST.c7=3` 后由 `syncLock()` 锁定整张⑦卡，条款不再单独维护锁状态。
4. 撤回签发必须填写理由并形成新审计记录。
5. 回退旧版本不会覆盖历史，而是创建新的“进行中”草稿。

## F. 回归

正式接入后需继续通过现有：`cdp_card`、`cdp_all5`、`cdp_rc`、`cdp_link`、`cdp_kn`、`cdp_sec`、`check_link.py`、`check_docx_link.py`、`js_check.js`，并新增本文件 A–E 的浏览器断言。
