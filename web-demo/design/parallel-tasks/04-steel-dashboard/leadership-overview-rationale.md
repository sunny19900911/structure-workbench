# 全院用钢量总览：领导端阅读逻辑

## 结论

领导端不应展示所有项目和单体，也不应先展示“项目数、已复核数、待补数”这类缺少行动含义的数字。首页只回答四个管理问题：

1. 哪些项目现在需要关注？
2. 四个组的项目分布是否稳定，哪里出现反复偏离？
3. 哪些规律可以沉淀为方案阶段参考带？
4. 哪些数据不完整，暂时不能形成结论？

## 推荐的信息层级

### 第一层：本期先看

只列需要领导判断、协调或追踪的少数事项，例如：

- 连续两个复核版本仍偏离同类区间；
- 数据缺口导致项目无法进入比较；
- 某类项目样本已经足够，可形成优秀参考区间；
- 某个组的项目离散程度持续扩大，需要专业复盘。

每条必须同时说明“为什么提示”和“下一步由谁处理”，不能只显示红色数字。

### 第二层：四个组的同类项目分布

以项目为圆点，按同类归一化指数展示分布：

`同类归一化指数 = 项目指标 ÷ 同类样本中位数 × 100`

指数 100 表示处于同类样本中位数附近。图表用来观察离散、偏移和连续变化，不用于组间或个人绩效排名。

同类样本至少应同时满足：

- 结构体系一致；
- 层数和高度处于同一分段；
- 抗震设防烈度、场地类别和地区条件可比；
- 地下室范围、基础形式和统计边界一致；
- 数据来自专业负责人确认的冻结版本。

样本不足时只显示“样本不足”，不计算优秀或异常结论。

### 第三层：重点项目与规律

默认只列异常项目、数据缺口和可复用基准，不展示全量清单。

- 重点项目：说明可比条件、当前信号和建议动作；
- 规律线索：按结构类型、基础形式、版本变化等维度形成待验证结论；
- 数据质量：单独标识缺面积、缺版本、未复核等情况，并排除出正式比较。

### 第四层：逐级下钻

领导需要时再按以下路径进入明细：

`全院 → 设计组 → 项目 → 单体 → 梁 / 柱 / 墙 / 板 / 基础`

全院层看重点和规律；设计组层看项目分布；项目层看同类条件和版本变化；单体层才查看具体工程量表。

## 不建议在领导首页展示

- 原始 TXT、Excel、source_id 和文件准确性；
- 所有项目、所有单体的平铺大表；
- 不区分结构条件的原始用钢量排名；
- 项目数、复核数、待补数三个独立大数字；
- 把单次偏离直接解释为设计质量问题；
- 把组间差异直接用于绩效评价。

## 数据持久化需求（提交主任务）

领导总览至少需要以下已复核字段：

- `group_id`、`project_id`、`building_id`；
- `version_id`、`version_no`、`review_status`、`reviewed_at`；
- 结构体系、层数、高度、地区、抗震设防烈度、场地类别；
- 地上面积、地下面积、基础面积、基础形式；
- 混凝土单方量、钢筋单方量、基础混凝土总量；
- 数据完整性状态、不可比原因、异常原因备注、负责人处理意见；
- 同类样本组编号、样本数量、中位数、四分位区间和归一化指数。

原始规范目录和原始文件不直接进入领导端；它们只作为项目内部数据来源留档。
