## 一致性核对

| 核对点 | 设计稿 | 最终实现 |
|---|---|---|
| 工作台外壳 | 保留现有顶栏、主导航与左侧目录 | 直接沿用完整工作台副本，无新建独立页面 |
| 项目层级 | 项目 → 单体 A/B → 三类材料表 | 已实现两个可展开单体，每个单体均有上部混凝土、钢筋、基础混凝土三个页签 |
| 钢筋口径 | 梁、柱、墙、板 | 实现按构件归并；不再显示纵筋、箍筋、直径空列或零值列 |
| 基础表 | 构件量、合计、基础面积、单方 | 已删除“个数”和零值等级列，增加占比、合计、基础面积和折算厚度 |
| 图表 | 钢筋和混凝土两个环形占比图 | 两图均由当前单体表格数据计算，图例同时显示百分比和绝对值 |
| 数据冲突 | 第1层板合计异常提示 | 显示 21 kg 与 57,159.059 kg 的冲突，并按分项求和等待负责人确认 |
| 负责人视图 | 直接查看材料明细 | 与设计人员共享同一项目台账，可查看来源、三张表、图表并确认或退回 |
| 响应式 | 单体和材料表在窄屏可用 | 文件卡、图表和基础摘要改为纵向，宽表在自身容器内滚动 |

## 首屏文字差异

- 设计稿使用概念性楼层和指标值；实现替换为 `主楼钢筋用量.xls` 的真实 13 层汇总值。
- 设计稿把三个材料页签放在图表上方；实现先显示来源文件和数据冲突，再显示图表与页签，以便负责人先确认来源。
- 实现增加“Demo 临时绑定”说明，避免把当前三类样本误写为已经完成项目/单体归属核对的数据。

## 有意保留的偏差

1. 单体 A 的钢筋来源为真实主楼表，但混凝土和基础来自 105 目录既有样本；页面明确标为临时绑定，正式接入必须通过 `project_id / building_id` 绑定。
2. 单体 B 使用 `DEMO-B-*` 构造数据，只用于验证两个单体的下拉和三材料表交互，不进入管理汇总。
3. 环形图采用页面原生 SVG，而不是图片资产，确保上传新文件后可随数据更新。

## 验证结果

- 新 `主楼钢筋用量.xls` 上传成功，识别 13 层。
- 钢筋汇总为 1,931.562 t，楼面面积 51,163.40 m²，含钢量 37.75 kg/m²。
- 基础混凝土合计 38,179.438 m³，基础面积 26,710.166 m²，折算厚度 1.429 m。
- 单体 A/B 展开、三个材料页签、负责人确认、角色切换均已验证。
- JavaScript 语法检查通过；桌面和 390×844 窄屏均已检查。
