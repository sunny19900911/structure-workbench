# 结构设计工作台操作简化与资料生成闭环优化

依据：USER-20261002-WORKFLOW（小香金猪本轮要求，原文事实）。本版先落实第1～3项，保留八个模块和原项目分区；第4项AI任务统一上下文和Token任务账单后续实施。已有局部改写、地区研判保留；聊天仅追加项目切换隔离，未调用付费AI验收。

## 怎么用

1. 顶部选择当前项目，点“导入资料”。建筑、地勘和模型都从此处上传；可按文件名识别类型，或手动选类型。模型选择所属单体，多份OUT作为同一批次。
2. 上传后自动整理并保存，点“查看扩初正文”。同一版本不会重复导入；来源列表提供替换、移除、恢复和归类更正。替换前先读取新资料，读取失败保留原资料。
3. 自动内容随资料和措施变化更新。人工正文保持原稿，受影响章节出现“比较资料变化”，可保留人工稿或采用本章更新稿。表格人工覆盖沿用原规则。
4. “处理问题 / 最终复核”集中显示缺项、资料与措施取值冲突、模型与措施差异；模型差异可展开对应原文。没有逐条确认候选或填写理由门槛。复核记录不等于系统完成工程验算。
5. 导出Word使用当前正文数据，并在同一项目留存导出快照。新建、示例、保存、备份、恢复移入项目管理菜单。

## 存储与边界

- `workflow-core.js` 比较各章的生成内容签名；没有变化的章节保留对象，不标记整篇过期，不自动请求DeepSeek。比较基线不重复保存图片数据。
- `regularity`、`unitTable`、来源历史、人工正文和项目ID不迁移、不清空。移除只影响项目引用，原文件只读。
- `main.exportHistory`存导出索引，`export-<id>`存对应HTML或原生Word模板块，复用`projectPart`和`expectedRevision`，避免多次导出把main撑大。项目备份包含这些分区。
- 大型地勘内嵌图片可能超过浏览器localStorage额度；成功保存的项目从项目库恢复。断网且浏览器缓存不足时不能承诺恢复最后未保存的大文件，须保留页面并重试保存。
- 失败项在本次页面中可单独重试；刷新后File对象不能恢复，需重新选择未成功导入的文件。已成功资料和正文不受影响。
- 当前仅扩初、措施和地方规范Word导出纳入内容版本存档；PPT、用钢量和计算书保留各自专用导出。
