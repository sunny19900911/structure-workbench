# 结构工作台 · 软件架构

最后核对：2026-11-14。本次为源码和既有记录核对，未重启正式服务。相对路径均以`web-demo`为根。

## 运行与数据流

```text
WorkBuddy / Kimi 本地客户端
  → stdio MCP（server/mcp-server.mjs）
  → 本机客户端（server/mcp-local-client.mjs）
  → 127.0.0.1 本地服务
      ├─ 项目存储、文件导入、导出接口
      └─ 浏览器桥 → 当前项目网页业务 → 同一项目存储

建筑 / 地勘 / OUT / 图片
  → 当前项目资料与参数 → 模板编排 + 人工修改
  → Word / PPT / 用钢量Excel / 计算书
```

浏览器参与组稿、PPT等业务，当前并非所有工具都可无页面执行。`BROWSER_REQUIRED`时应打开目标项目页面；不能把本地网页地址当成MCP地址。

## 数据管理

便携版默认数据根为`%LOCALAPPDATA%/StructureWorkbench`；`WORKBENCH_PORTABLE_DATA`或发行包`data-folder.txt`可改变位置。必须用实际服务数据根确认当前项目，不由页面端口推断。

| 数据 | 保存方式 |
|---|---|
| 主参数及计算书 | 同项目`main`分区 |
| 建筑、地勘、来源及查表条件 | `intake`分区 |
| 扩初 | 按单体的`expansion-*`分区，使用稳定项目ID |
| PPT文稿与图片 | `ppt`分区，按单体隔离 |
| 用钢量等模块 | `modules`分区 |
| 输入文件夹关联 | `folder-binding`分区 |
| 上传PDF | 数据根下`calculation-uploads`，需随项目库保留 |

保存采用`expectedRevision`；409后重新读取，不强制覆盖。服务端使用临时文件、刷盘、rename发布不可变修订；损坏读取有校验与回退。历史记录不在本轮自动清理。

关联输入文件夹的MCP成果写入该目录`工作台成果/<批次>`；未关联时写入数据根`exports/MCP/<日期>`。网页下载仍受浏览器下载设置影响，不能承诺所有导出都自动进入项目目录。

## 参数和人工稿

统一措施由`measures.update`或`measures.table`调用现有联动；网页与MCP共用实现。章节修改使用当前原文及修订检查，保留相邻节和人工内容。资料变化不等于工程取值已批准，历史项目值不能静默成为当前项目事实。

参数到所有成果位置的完整映射表尚未展开，不在本次架构文档中假装已建成。后续按用户选定范围讨论。

## MCP启动区别

- `deploy/portable/mcp.cmd`当前通过`launch.ps1`启动服务/页面。
- stdio真正入口为随包`runtime/node/node.exe`加`app/server/mcp-server.mjs`绝对路径。
- `mcp-setup.mjs`生成客户端配置，移动解压目录后需重新生成；保留客户端其他连接。
- `workbench_status`纯读；`workbench_start`显式启动服务，`workbench_open`还打开页面。
- 启动器与MCP按数据目录共用服务锁，核对版本和实例身份。网页任务超时结果未知时先读回结果，不重放写入。
